# Voicemeeter Potato manual, pages 31-45

## Crossover example / Mix Down formulas, first appearance (p.31)

- **Stereo Repeat + Master EQ as active crossover** (p.31): worked
  example — a 3-way JBL speaker stack (High/Mids/Bass amps) driven by
  the bus EQ's 6 cells configured as HPF (ch5/6), Band Pass = LPF+HPF
  (ch3/4), and LPF (ch1/2), illustrating the p.30 crossover technique
  concretely.
- **MIX DOWN A formula** (p.31, exact vendor text): `LEFT = FL + (70%
  FC) + SW + RL - SL`, `RIGHT = RL + (70% FC) + SW - RR + SR`.
- **MIX DOWN B formula** (p.31, exact vendor text): `LEFT = FL + (70%
  FC) + SW + RL + SL`, `RIGHT = RL + (70% FC) + SW + RR + SR`.
  NOTE: both formulas' RIGHT side uses `RL` (rear-left) as its own base
  term rather than `FR` (front-right) — this is the same
  `RL`-vs-`FR`-looking discrepancy `docs/SPEC.md` section 1.6 already
  flags as a probable vendor-manual typo (its own comment: "the published
  Mix Down formulas literally use RL on the right hand side of the RIGHT
  channel, which looks like a typo for FR"). Confirmed reproduced
  verbatim in Potato's manual too, both here and again in the p.34 full
  BUS-mode table — not a one-off transcription error in this specific
  printing.

## Composite mode (p.32)

- **Composite Mode** (p.32): the bus's 8 channels can each be composed
  from any pre-fader or post-fader input, or the bus's own default
  channel — configured via the System Settings dialog box's Composite
  Patch.
- **Composite Patch UI** (p.32): "PATCH COMPOSITE" panel, one assignable
  slot per bus channel (8 total) — example shown: `BUS ch1`, `BUS ch2`,
  `IN#1 Left`, `IN#2 Left`, `IN#3 Left`, `IN#4 Left`, `IN#5 Left`, `IN#5
  Right` (each slot is a button selecting its source).
- **PRE/POST-Fader patch toggle** (p.32): clicking the "Select PRE-Fader
  Inputs..." text label switches the whole patch to "Select POST-Fader
  Inputs..." mode instead (a single mode switch for the whole patch, not
  per-slot).
- **Recording use case** (p.32): composite signal lets you record up to
  8 channels composed from any Voicemeeter inputs, a DAW via virtual
  ASIO, or the integrated recorder — e.g. recording a VOIP interview or
  conference for post-production with up to 8 separate tracks.

## Additional bus-mode use cases / 8x8 Gain Matrix (p.33)

- **Channel-extraction use cases** (p.33, since v2.0.3.4): example
  scenarios for the up-mix/extract bus modes — send the LFE channel to a
  dedicated subwoofer/Buttkicker/Subpac device; send the 5.1 rear
  channels to a Bluetooth wireless speaker; send the Center channel to a
  specific speaker device; drive a 2.1/4.1/5.1/7.1 PA system from a
  stereo source.
- **8x8 Gain Matrix** (p.33): a free standalone companion application
  (built from the Remote API SDK's example) providing one full 8x8 gain
  matrix on a selected bus, to redistribute a 5.1/7.1 signal's 8 channels
  across a different multichannel speaker layout. Distributed via the
  VB-Audio forum, not bundled in the main installer.

## All 12 bus modes, exact formulas (p.34)

The manual's own reference table, in its own order — cross-reference
directly against `loomix-core::bus_mode::BusMode` and `docs/SPEC.md`
section 1.6:

1. **Normal Mode**: all 8 channels sent as-is.
2. **MIX DOWN A**: `LEFT = FL + (70% FC) + SW + RL - SL`, `RIGHT = RL +
   (70% FC) + SW - RR + SR`.
3. **MIX DOWN B**: `LEFT = FL + (70% FC) + SW + RL + SL`, `RIGHT = RL +
   (70% FC) + SW + RR + SR`.
4. **STEREO REPEAT**: `ch1=FL, ch3=FL, ch5=FL, ch7=FL`; `ch2=FR, ch4=FR,
   ch6=FR, ch8=FR`.
5. **COMPOSITE MODE**: contains the pre-fader (or post-fader, per the
   toggle) inputs given by the Composite Patch.
6. **UP MIX TV** (stereo → 7.1): `FL=L, FC=20%(L+R), RL=70%(L-R),
   SL=70%(L-R)`; `FR=R, SW=50%(L+R), RR=70%(R-L), SR=70%(R-L)`.
7. **UP MIX 2.1**: `FL=L, FR=R, SW=50%(L+R)`.
8. **UP MIX 4.1**: `FL=L, FR=R, SW=50%(L+R)`; `RL=L, RR=R`.
9. **UP MIX 6.1**: `FL=L, FR=R, SW=50%(L+R)`; `RL=L, RR=R, SL=L, SR=R`.
10. **CENTER ONLY** (extract center): `LEFT=FC, RIGHT=FC`.
11. **LFE ONLY** (extract subwoofer): `LEFT=SW, RIGHT=SW`.
12. **REAR ONLY** (extract rear): `LEFT=RL, RIGHT=RR`.

## Special FX section overview (p.35)

- **Special FX: stereo reverb + stereo MultiTap Delay** (p.35,
  Potato-only): via regular per-strip SEND and per-bus RETURN knobs.
  Every physical input gets a rotary knob to send its signal into the
  Reverb and the MultiTap Delay.
- **POST send-mode button** (p.35): per strip, switches the FX send
  between PRE-fader and POST-fader (in POST mode, the send level also
  depends on the strip's own gain slider).
- **Per-bus FX return knobs** (p.35): every bus gets a rotary knob for
  the reverb return and one for the delay return, controlling how much
  of each effect reaches that bus.
- **Internal Reverb: JustVerb III** (p.35): a version of the AphroVx
  reverb series (1999), adapted 2006 for the Innovason live console
  (Analog Devices SHARC DSP). Includes a 3-band full parametric EQ to
  shape the reverb's color, and 10x3 (10 types × 3 sizes) presets.
- **JustVerb III: DRY** (p.35): amount of original (unprocessed) signal;
  typically minimized when used via send/return.
- **JustVerb III: WET** (p.35): amount of reverb effect; typically 0.0dB
  when used via send/return.
- **JustVerb III: DELAY** (p.35): pre-delay, up to 1000 ms.

## JustVerb III detail / MultiTap Delay (pp.36-37)

- **E.Ref (early reflection)** (p.36): amount of early-reflection
  reinforcement at the start of the reverb tail.
- **DECAY** (p.36): reverb time, 50% to 200% of the preset's own decay
  (1.0 = 100% = the original preset value); UI shows a 0.5x/2x range with
  the current factor (example: 1.42s shown).
  - Full control surface shown: reverb-type buttons **Plate / Room /
    Hall**, each with **Short / Med / Large** size variants; **Dry**
    knob (example -inf shown); **Wet** knob (example 0.0db shown);
    **Delay** knob (example 20ms shown); **E.Ref** knob (example 0%
    shown); **Decay** knob (example 1.42s shown); a **Preset** row of 7
    named presets — **Vocal, Church, Stadium, Club, Soft, Pipe,
    Special** — each again with Short/Med/Large; a 3-band **EQ** section
    (Hz / Gain / Q per band, plus a response graph, dB range shown
    -18..+18, frequency axis 10Hz-10000Hz); a **BYP** (bypass) button per
    section — one for the whole reverb (soft bypass), one for just the
    EQ.
- **Internal Delay: MultiTap 8** (p.36): also from the 2006 Innovason
  console; manages 8 stereo taps on a musical timeline for rhythmic
  delay effects. Each tap has its own gain, left/right pan, and an
  LPF/HPF filter.
- **Timeline display** (p.36): a large LCD shows the taps' positions on
  a musical-beat scale (4/4 on top, 3/4 on bottom); a Gain Timeline
  defines each tap's gain/delay, a Pan Timeline defines each tap's pan.
  The musical scale is derived from the current Tempo (BPM); a Time
  Ratio knob rescales the current rhythm to a different tempo.
- **MultiTap Delay: DRY/WET/PRE-DELAY** (p.36): same convention as the
  reverb — DRY (original signal, minimized on a send/return path), WET
  (effect amount, typically 0.0dB on send/return), PRE-DELAY (up to
  1000ms). **BYPASS**: soft-bypasses the whole delay effect.
- **Balance knobs** (p.37): two knobs treat the left/right input channels
  independently, letting you rebalance them to mono or a reverse-stereo
  input.
- **Full MultiTap Delay control surface** (p.37, from the screenshot):
  Balance section (Left/Right pan knobs, C/L/R detents); Delay Controls
  — **Delay** (example 545ms), **Gain** (example 95%), **Pan** (example
  "L"), **Filter** (example 10%, Lo/Hi), **Time Ratio** (example 1.00);
  Dry/Wet Mix — **Dry** (example -inf), **Wet** (example 0.0db); **Pre
  Delay** (example 0ms); **Feedback** (example 0%); a **Taps** selector,
  1-8; **Set Note** button; **Tap**/tempo-detect button with a BPM
  readout (example 120.0) and a **Scale Fit** toggle; gain-timeline and
  pan-timeline graphs with per-tap markers.
- **Feedback knob** (p.37): loops the delay's output back into its own
  input (feedback amount, as a percentage).
- **Set Note button** (p.37): opens a dialog to set a tap's delay time as
  a musical note duration, relative to the current Tempo.
- **TAP tempo-detect button** (p.37): tap in rhythm with what you hear to
  define a new tempo; after 4 taps the new tempo blinks red; the "Scale
  Fit" button commits it. The Time Ratio knob can then rescale the
  current tap rhythm to the new tempo, and "FIX DELAY" writes that scaled
  ratio into every tap's actual delay value (resetting Time Ratio to 0).
- **AUTO FIT toggle** (p.37): when on, a newly detected tempo is applied
  automatically, rescaling every active tap's delay to preserve the same
  rhythm at the new tempo — no manual Time Ratio/Fix Delay step needed.

## Internal MultiBand Compressor: C5 (pp.37-39)

- **C5 overview** (p.37): originally built 2007 for the Innovason
  console (later superseded there by "C4"); available in Potato to apply
  multiband compression to hardware inputs.
- **C5/Delay are mutually exclusive** (p.37): C5 must first be selected
  in the System Settings dialog's "Internal FX Selection" (a Reverb/C5
  toggle for the *first* slot) — actually shown as a **Delay ↔ C5**
  toggle: engaging C5 replaces the MultiTap Delay entirely, they are not
  simultaneously available (both occupy the same second internal-FX
  slot, alongside the always-present Reverb).
- **C5 layout** (p.38): 5 frequency bands, each showing input, output,
  and gain-reduction meters, each with its own full compressor/limiter.
  4 controls between the bands (below the meters) set the 5 bands'
  crossover frequencies (example split points shown: 86.1 / 344.5 / 1376
  / 5513 Hz).
- **Per-band parameters** (p.38): **Gain** (input gain before
  compression, e.g. 0.0db default); **COMPRESSOR** on/off toggle;
  **Threshold** (e.g. -19.9db default); **Ratio** (e.g. 7.2 default);
  **Attack** (per-band example values 10/8/6/4/2 ms across bands 1-5);
  **Release** (example 60/55/50/45/40 ms); **Knee** (e.g. 50.0%
  default); **Out Gain** (post-compression gain, e.g. 0.0db default);
  **LIMITER** on/off toggle; **Limit** (brickwall ceiling, e.g. 0.0db
  default); **Distortion** (e.g. 5.0% default) — controls the limiter's
  reaction speed: more distortion = faster/harder limiting, less =
  slower/softer.
- **Master C5 controls** (p.38-39): **OUTPUT GAIN** knob (final output
  gain, example 4.4db); **AUTO MAKE UP** toggle (auto-computed output
  gain compensating compression, across all bands); **BYPASS** (whole C5
  processing); **LINK Type** selector — ABSolute / RELative / fully
  independent — controls how editing one band's parameter affects the
  others; **SOLO/MUTE** per band (audition individual bands); settings
  save/load via the dialog's own sys-menu.
- **C5 routing caution** (p.39): to compress a hardware input via C5,
  that strip's own BUS assignment buttons must be turned fully OFF if
  every target bus already receives the C5 return — otherwise the signal
  doubles (once via the C5 return path, once via the strip's direct bus
  assignment). The strip's **POST** button (post-fader = after gain
  slider and mute) then lets the fader control the level actually sent
  into C5.

## External FX / ASIO routing (pp.39-40)

- **External FX (two true AUX sends)** (p.39): regular SEND/RETURN
  knobs; functional only when the External FX I/O is assigned to an ASIO
  channel, on the ASIO device currently selected as output A1 (which
  must have enough spare channels).
- **Full ASIO routing** (p.40): selecting an ASIO device as output A1
  lets you route every physical input, physical bus, and the External FX
  paths across up to 64 I/O channels — described as the optimal way to
  run Voicemeeter with a professional audio interface. Achieved by
  selecting "no device" for a given physical input/bus in system
  settings, which then exposes ASIO channel-assignment fields for that
  input, or for buses A2-A5 (bus A1 itself always uses the ASIO driver's
  first 8 output channels, non-configurable).
- **Worked example** (p.40): physical inputs #1-4 from ASIO channels 1-8;
  input #5 from a separate USB microphone (a WDM device, not the ASIO
  device); bus A1 auto-uses ASIO channels 1-8; A2 → ASIO out 10+11; A3 →
  ASIO out 17-22 (6ch); A4 → ASIO out 63-64 (stereo monitor); A5 → a
  separate WDM speaker device.
- **Channel-overlap warning** (p.40): bus outputs are copied onto ASIO
  output channels in strict logical order A1, A2, A3, A4, A5 — if two
  buses' assigned channel ranges overlap, the later bus's channels
  silently overwrite the earlier one's (A2 can replace A1's channels,
  A3 can replace A2's, and so on).
- **External FX ASIO routing** (p.40): works only when the ASIO driver is
  connected as output A1; routed via a dedicated "External FX Patch".
  Worked example: Send 1 knob → ASIO output channels 32+33 (stereo AUX);
  Return 1 comes from ASIO input channels 40,41 (stereo return).

## Integrated recorder (pp.41-42)

- **Tape-deck transport** (p.41): playback formats WAV, AIFF, MP3, M4A,
  MP4, MOV, AVI, WMA, WMV; recording formats WAV, BWF, AIFF, MP3.
  Controls: current filename/directory display, current input-level
  meter, sound-format display (example: 44100Hz, 2ch), bus-routing
  buttons for playback (A1/A2/A3/B1/B2), current armed strip/bus
  indicator, REW / FF / Play / Stop / Record-Pause transport buttons.
- **Playback selection / auto-naming** (p.41): click the cassette icon
  to pick a file to play back; click the progress bar to seek. Recording
  can start at any moment and auto-names the file `Record <date> at
  <time>.wav` (example: `Record 2015-01-02 at 11h23m24s.wav`) into the
  Documents/Voicemeeter folder.
- **Recorder Options dialog: I/O arming** (p.41-42, right-click the tape
  deck): **PRE-FADER INPUTS** — arm any of the 8 named strips
  individually (Physical Input #1-5, Virtual, Virtual AUX, Virtual 3) to
  be recorded (mixed together in stereo). **POST-FADER OUTPUTS** — arm
  exactly one bus's output instead (Physical BUS A1-A5, Virtual BUS
  B1-B3; example shows Physical BUS A3 armed). Also: **Target
  Directory** field; **Prefix Name** field; **File Type** dropdown
  (example BWF); **Sample Rate** field (example 44100 Hz); **Bit
  Resolution** field (example 16 Bits); **Channels** field (example 2);
  **MULTITRACK OPTION** toggle (example "No", generates 2 mono BWF files
  when enabled in this example); **Play On Load** toggle (example Yes);
  **Loop** toggle (example No); **Playback Gain** slider (example
  labeled "Fader Gain", 0dB); **Stop Record After Duration** toggle
  (example No).
- **PRE-FADER INPUTS semantics** (p.42): records one or all inputs
  summed to stereo, independent of fader gain and all FX/mute/solo
  state — captures the original incoming signal, sources mixed at their
  original (unprocessed) gain.
- **POST FADER OUTPUTS semantics** (p.42): records a chosen bus's actual
  output (2 to 8 channels), including Composite-mode content — i.e.
  records exactly what you'd hear on that bus. A bus doesn't need to be
  connected to a real audio device to be used purely as a recording
  source.
- **File options** (p.42): target directory and filename prefix, each
  set by clicking the field (prefix defaults to "Record" if unset).
- **Pre-recording buffer** (p.42): Voicemeeter continuously records into
  a rolling buffer (20 seconds allocated by default); a configurable
  value in seconds (0 = disabled) determines how much of that buffer is
  prepended to a file when Record is actually pressed.
- **File type / independent sample rate** (p.42): WAV, BWF, AIFF, or MP3
  (32-320kbps); MP3 records stereo only, the others support up to 8
  channels when recording a bus. The recording file's format — including
  its sample rate — is fully independent of Voicemeeter's own running
  engine rate (example given: recording at 48kHz while the engine runs
  at 44100Hz).
- **Multitrack option** (p.42): if enabled, generates one file per
  track/channel, each suffixed `_Track1`, `_Track2`, etc.
- **Play On Load** (p.42): auto-plays a file immediately once selected.
- **Loop** (p.42): continuous playback loop.
- **Playback Gain** (p.42): a slider controlling the gain of file
  playback specifically.
- **Stop Record After Duration** (p.42): a timer that auto-stops
  recording after a set duration (00:00:00 disables it) — useful for a
  movie or podcast of known length.

## Other Voicemeeter tools & accessories (p.44)

- **8x8 Gain Matrix** (p.44, standalone companion app): a single 8x8 gain
  matrix applicable to a selected bus, to redistribute audio channels
  across different multichannel speaker layouts; built from the Remote
  API SDK's own example.
- **15-band graphic EQ** (p.44, standalone companion app, "Graphiq EQ"):
  a 15-band graphic EQ applicable to a selected bus; useful for tuning a
  stereo-only P.A. system.
- **VBAN2MIDI** (p.44, standalone app): sends a VBAN-MIDI stream from a
  physical MIDI input device, or delivers an incoming VBAN-MIDI stream to
  a physical MIDI output. Two instances cannot share the same UDP port.

## Streamer View (pp.44-45)

- **Streamer View overview** (p.44-45): a simplified, resizable GUI
  installed alongside Voicemeeter, for controlling it either directly
  (Remote API, same computer) or over the network (VBAN); launchable from
  the main menu or the Windows applications list — a separate, regular
  application, not a panel of the main window.
- **Label-gated visibility** (p.45): only strips/buses that have been
  given a label appear in Streamer View (right-click a slider's bottom in
  the main Voicemeeter window to set its label).
- **Direct sub-mix access** (p.45): Streamer View's main benefit with
  Potato is quick access to per-bus sub-mixes (e.g. adjusting the mix
  sent to output A1 vs. virtual output B1/"Skype" vs. B2/"OBS")
  because it shows one gain slider per bus, per strip.
- **MON button** (p.45): per bus, listens to that particular bus,
  according to the monitoring option configured in the System Settings
  dialog.
- **Monitoring BUS setting** (p.45): defines which output bus you
  actually hear when using a MON button to monitor a selected bus.
- **Slider Mode** (p.45): recommended set to RELATIVE for remoting
  consistency, so per-bus sub-mixes keep their relative differences when
  a MIDI controller drives a strip's gain slider.
- **Streamer Slider Mode** (p.45): a local mode governing how strip
  sliders move together — **NO LINK** (fully independent), **ABSolute**
  (fully dependent, move together identically), **RELative** (move
  together preserving relative offsets).
- **Connection sys-menu** (p.45): the dialog's own top-left icon menu
  configures the connection type to Voicemeeter — **DIRECT** (same
  computer) or up to 4 simultaneous **VBAN** connections (to control
  Voicemeeter on another computer on the network).
