## System Settings / Options dialog (p.77-79)

- **System Settings dialog** (p.77): opened from the main menu. A modal dialog showing live status of every audio device currently used by Voicemeeter Banana.
- **Per-device status rows** (p.77): IN1/IN2/IN3 Physical Input, OUT A1 Main Device, OUT A2, OUT A3 — each shows Status (ON/OFF), driver name (e.g. "WDM: Speakers (Roland Rubix 24)"), SR (sample rate), buf (buffer size), ch (channel count), r (bit resolution, e.g. "r:24").
- **Buffering fields** (p.77): Buffering MME (default 1024), Buffering WDM (default 512), Buffering KS (default 512), Buffering Clock (default 512, used by the internal-clock fallback), Buffering ASIO (Default or a forced value) with an SR field (Default or forced samplerate).
- **Monitoring Synchro Delay fields** (p.77): OUT A1/A2/A3, each 0.00 ms by default — a per-output monitoring delay.
- **OUT Limiter toggle** (p.77-78): On/Off, enabled by default; enables brick-wall limiters (VB-Audio C-Limiter) on every output bus; when off, a simple peak remover is applied instead.
- **VAIO sync field** (p.77-78): e.g. "STRICT" — strict mode synchronizes all virtual I/O tightly with the main stream (given by output A1), for stability especially at small latency.
- **Virtual ASIO Type field** (p.77): e.g. "Float32LSB".
- **WDM Input Exclusive Mode field** (p.77): Yes/No.
- **Preferred Main SampleRate field** (p.77): e.g. 48000 Hz.
- **Engine Mode field** (p.77): e.g. "Normal".
- **PATCH COMPOSITE row** (p.77, recap from earlier pages): select PRE-Fader inputs used by Composite Mode, one selector per of the bus's 8 channels.
- **PATCH INSERT grid** (p.77, recap): activate insert per pre-fader input, 22 channels via the virtual ASIO driver, with a PRE-FX/POST-FX toggle.
- **Status field meanings** (p.78): **SR** = current device sample rate (can differ per device — the engine is multi-point/multi-format); **buf** = current buffer size for that audio point; **Ch** = channel count managed (1-2 on inputs, up to 8 on outputs); **r** = bit resolution (Banana defaults to 24-bit); **S** = share mode indicator, applicable to WDM only (KS is usually exclusive, MME is usually shared; WDM depends on device and engine mode).
- **Output A1 as master configuration** (p.78): A1's device configuration sets Voicemeeter's overall audio configuration and the virtual ASIO driver's sample rate/buffer size; all internal processing runs at this sample rate, with automatic conversion for any point running at a different rate.
- **Internal Clock fallback** (p.78): if no device is selected as output A1, Voicemeeter runs on its own internal clock using the preferred sample rate and the Buffering Clock parameter — letting it run with no physical output device at all.
- **Buffer size / latency tradeoffs** (p.78): MME supports 512-2048 samples; WDM and KS can go down to 256 samples (close to real time, usable for real-time karaoke or digital piano performance). Some PC configurations don't tolerate small buffers well (unstable stream, audio cuts) — hence MME defaults to 1024 and WDM to 512 as broadly safe values.
- **Engine mode SWIFT / WDM Input Exclusive Mode — disabled** (p.78): both experimental options exist in code but are noted as disabled in this version "because generating too much support" (i.e. caused enough support burden that the vendor turned them off) — SWIFT aimed to improve real-time performance experimentally; WDM Input Exclusive Mode forced smallest-buffer exclusive-mode WDM input, at the cost of stability (can cause a WASAPI exclusive-mode bug per the Known Issues section).

## ASIO Driver support (p.79)

- **ASIO as output A1** (p.79): lets Voicemeeter run in "audio pro" conditions like any ASIO-based DAW. If an ASIO device is output A1, Voicemeeter sends audio to its first 8 output channels; other busses can be routed to other ASIO output channels; input channels of the ASIO device can be patched to Voicemeeter's Hardware Inputs via "PATCH ASIO Inputs to Strips" (per-strip left/right channel selectors).
- **ASIO buffering/samplerate options** (p.79): Buffering ASIO can use the device's own default buffer size, or be forced to a specific size (driver may refuse or misbehave for some values); SR can use the ASIO driver's default sample rate or force the "Preferred Main SampleRate".
- **Open ASIO Control Panel from the device name** (p.79): clicking the ASIO device's name in the status dialog opens that driver's own control panel.
- **Getting optimal latency** (p.79-80): output A1's device choice is critical (sets master sample rate and main buffer size); ASIO preferred, WDM/KS otherwise. Reducing latency buffer size (e.g. down to 256) can further reduce global latency, especially with WDM/KS devices.
- **SWIFT mode mentioned again as an option to reduce mic-to-speaker time** (p.79-80): "not recommended because might be unstable."
- **VAIO internal latency tuning via VBCABLE Control Panel** (p.80): can further optimize virtual I/O latency, though decreasing it can produce discontinued/non-working streams in some cases.
- **Virtual ASIO driver's own added latency** (p.80): adds a single buffer's worth of latency to the global chain, sized by output A1's buffering.
- **LATENCY WARNING** (p.80, in red in the manual): "CHANGING DEFAULT LATENCY, BY REDUCING BUFFER SIZE CAN DECAY THE AUDIO STREAM, BRING UNSTABILITY, FREQUENT AUDIO CUT, STATIC, SYNCHRO LOST (ROBOTIC VOICE)." Recommendation: revert to default buffer size if this happens. This is the manual's own explicit naming of "robotic"/glitchy-audio symptoms as a buffer/latency misconfiguration class, distinct from the frames-vs-samples bug this project separately diagnosed and fixed — worth noting as a datapoint, not a claim the two are the same issue.

## Patch Composite / Patch Insert (p.80-81)

- **Patch Composite recap with UI detail** (p.80): 8 channel-selector buttons (BUS ch1, BUS ch2, IN#1 Left, IN#2 Left, IN#3 Left, IN#4 Left, IN#5 Left, IN#5 Right by default), each clickable to assign a different Voicemeeter input source to that composite-mode channel slot; a separate click toggles the whole row between PRE-FADER and POST-FADER input sourcing. Used to build a composite signal on a bus for multitrack sending/recording.
- **Patch Insert** (p.81): activates a pre-fader insert per input channel, applicable only when an application is connected to the "Voicemeeter Insert ASIO Virtual Device Driver". Supports a single client working as a pre-fader insert across up to 22 channels spanning the 5 strips (e.g. to run a VST plug-in host and insert plugins on any Voicemeeter input).
- **Patch Insert grid** (p.81): a row of toggle cells (one per input channel: in1 Left/Right, in2 L/R, in3 L/R, in4 L/R/C/LFE/SL/SR/BL/BR, in5 same 8-channel set) plus a PRE-FX/POST-FX insert-point selector.
- **Insert-active indicator** (p.81): when a DAW/ASIO app is connected to the Insert driver, a small "i" icon appears top-left of each strip whose INSERT return is active.
- **Tested with Minihost Modular** (p.81, Image Line company app, www.image-line.com): shown as a working example VST host for the insert path. Manual notes the virtual insert point in that example is set to POST-FX but is "always PRE-FADER" regardless of the PRE-FX/POST-FX setting (i.e. the insert always happens before the strip's fader, only its position relative to on-strip FX like the pad/EQ is configurable).

## M.I.D.I. Mapping (p.82-84)

- **MIDI Mapping dialog** (p.82): connects a MIDI remote surface to control gain, mute, solo of every strip and bus (with MIDI Feedback), plus a secondary MIDI controller ("MIDI Extra Input Device").
- **Dialog fields** (p.82): M.I.D.I. Input Device, M.I.D.I. Output Device (feedback), M.I.D.I. Map Name, M.I.D.I. Extra Input Device, VBAN M.I.D.I. input (e.g. "OFF"), buttons: Reset Map, Load M.I.D.I. Map, Save M.I.D.I. Map, Refresh Controller.
- **Per-control mapping rows** (p.82, 2 pages of rows, paginated "Page 1/2" etc.): each row is a Voicemeeter control (e.g. "Gain Fader Strip #1", "L/R PAN Strip #1", "Mute Strip #1" with a "PTT" tag, "Solo Strip #1", "EQ High Virtual Strip #4", "Gain of BUS A1") paired with a Learn button, a MIDI code display/edit field (e.g. "Control Change 1", "Note On E-1 (16)"), and an F/FF feedback-mode toggle.
- **Learn workflow** (p.82): select the MIDI device, click Learn (Tab or Up/Down arrow to move to next/previous control while learning), move the physical control; click the MIDI code area (black) to reset that control's mapping.
- **PTT tag** (p.82): "Push To Talk" — a Mute control tagged PTT un-mutes the related strip while the physical button is held down, and re-mutes on release (momentary behavior, distinct from a toggle mute).
- **Reset Map / Load / Save Map** (p.82): reset the entire MIDI mapping; recall/save a mapping to/from an XML file, nameable via "M.I.D.I. Map Name".
- **Refresh Controller** (p.83): sends all MIDI feedback messages for the current Voicemeeter state at once; also available as a MIDI function assignable to a MIDI button.
- **MIDI Feedback: F (simple) vs FF (double)** (p.83): F mode sends feedback to the controller only when the related control changes via something other than that same controller (mouse, VBAN request, etc.) — adequate for ordinary knobs/faders. FF mode double-feeds-back, needed for LED buttons (must light to match the Voicemeeter button's state) and some motorized faders that need explicit position acknowledgement (otherwise the fader can spring back to its prior position, depending on remote surface type).
- **MIDI Forward** (p.83): incoming MIDI mapping messages (from 2 different physical MIDI controllers, and from an incoming VBAN-MIDI stream) are all also forwarded automatically to the MacroButtons application. Since March 2021, MIDI messages (including feedback) can also be forwarded out over an outgoing VBAN-MIDI stream, to reach a MIDI controller sitting on a different computer.
- **MIDI Advanced Feedback (since November 2022)** (p.84): lets a 2-position control define custom feedback values instead of the default 127 (ON) / 0 (OFF) — useful for a MIDI control that can display different colors. Opened by right-clicking the "F" button, exposing: Feedback Value ON, Feedback Value OFF (both default 127/0), Feedback Message ON (HEXA) and Feedback Message OFF (HEXA) free-form boxes for defining a complex feedback message (including sys-ex) to drive other MIDI-controlled gear (e.g. a MIDI LCD or machine-control surface).
- **Duplicate-MIDI-message highlighting** (p.84): a MIDI code already used by another mapped control is shown highlighted in yellow; right-clicking it lists the other parameter(s) sharing that same MIDI message.

## Voicemeeter Banana I/O Diagram (p.86)

- **Full signal-path I/O diagram** (p.86): a labeled schematic mapping every physical/virtual input and output. Physical Audio Devices (WDM/KS/MME) feed Stereo Input #1-#3. Voicemeeter Virtual Input and Voicemeeter Virtual Aux Input each expose a Voicemeeter ASIO and Voicemeeter AUX ASIO channel block (channels 1-22, labeled Left/Right/FC/LFE/SL/SR/BL/BR per group of 8, corresponding to Input #4 and Input #5's "8 channels Virtual Input"/"8 channels Virtual Aux"). A "Voicemeeter Insert ASIO" row (Left/Right per strip 1-3) sits alongside. On the output side, Hardware Outputs (A1/A2/A3) and Virtual Outputs (B1/B2) are each exposed via WDM/KS/MME/Direct-X and a "Voicemeeter AUX ASIO"/plain ASIO block, with the same 8-channel-per-group labeling (FL/FR/FC/LFE/SL/SR/BL/BR).
- **Windows Sound integration recap in the diagram** (p.86): shows "VoiceMeeter Aux Input"/"VoiceMeeter Input" as playback devices (feeding the Virtual Inputs) and "VoiceMeeter Aux Output"/"VoiceMeeter Output" as recording devices (fed by B1/B2) — same wiring already described on page 17, now shown alongside the full channel-numbered ASIO picture.

## Voicemeeter License / About box (p.87)

- **Donationware licensing model** ("Simple donationware")** (p.87): free to use with all functions available (except optional/extra-cost features like VAIO Extension); users are expected to pay if they find it useful or use it professionally; price is selectable at 5 tiers via the webshop (lowest = renewal price, default = recommended price, highest = R&D support tier).

## VAIO Extension License Dialog Box (p.88-90)

- **VAIO Extension** (p.88): an optional feature, "donationware for activation code" — enables extra VAIO routing (for stereo input strips and from physical BUS A1/A2/... per the dialog's own graphic) once activated. Activation email/response-code flow described (Registered e-mail, Challenge code — tied to the specific PC — Response code, an Activate/Activated indicator).
- **License-per-PC-slot model** (p.88): each purchased VAIO Extension license creates a slot in the user's webshop "My License" account page, retrievable/regenerable (a "REGEN" option) for a PC change or a second PC.
- **Challenge code stability** (p.88): normally stable across a Windows update; can change after a Windows re-installation, a CPU change, or (possibly) a motherboard/all-Ethernet-devices change. License is per-PC and non-transferable per the vendor's general terms.
- **Hide e-mail address** (p.89): right-click the ACTIVATED indicator to toggle hiding the registered e-mail; stored in the registry.
- **Use Computer Footprint** (p.89): if activated and the PC has a network adapter, the computer's "footprint" can be exported (e.g. to a USB key) via right-click on the challenge code, and re-imported after a Windows reinstall (with the registered e-mail and previous response code) to re-activate without a new response code.
- **Activation Log** (p.89): `Voicemeeter_ActivationLog.dat` in My Documents\Voicemeeter records the activation history on that PC; can be manually copied/pasted across a Windows reinstall, and is useful for vendor support if activation problems recur.
- **License Activation Process** (p.90): on first install, activation fields are empty; a unique Challenge code is generated per-PC (8 hex digits + a suffix letter, e.g. "H8545AB60B"). "BUY ONLINE" pre-fills the challenge code on the vendor webshop page; the webshop lists 5 contribution tiers (P1-P5, "I'm a fan" through "I support the R&D team") at a shown price (e.g. 15,00 EUR tax excl. in the example); after payment, the Response code and license details are available on the "My License" account page.
