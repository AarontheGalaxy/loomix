# Voicemeeter Potato manual, pages 46-60

## Streamer View VBAN connections (p.46)

- **Streamer View connection sys-menu, exact items** (p.46): Direct
  Connection, VBAN #1 Connection, VBAN #2 Connection, VBAN #3
  Connection, VBAN #4 Connection, VBAN Configuration... — the sys-menu
  named on p.45, now itemized.
- **VBAN Configuration dialog (from Streamer View)** (p.46): a table of
  4 rows (VBAN #1..#4), each with **Stream Name**, **IP Address To**,
  **UDP port** fields (example port 6980, distinct target IPs per row).
  Caption warns: to use a VBAN connection with Voicemeeter on the *same*
  PC, define a different UDP port (e.g. 6981) for VBAN Services ("RT
  packet"); also: "VBAN Incoming Command Stream must be activated on
  Voicemeeter" for this to work at all.
- **Multi-client remoting** (p.46): the VBAN Command protocol / RT Packet
  service supports multiple simultaneous clients — e.g. 2+ Streamer Views
  can control the same Voicemeeter instance from different rooms at once,
  alongside a separate PC's Macro Buttons app sending VBAN commands to
  that same instance concurrently.

## Preset Scene (p.47)

- **Preset Scene list** (p.47): 64 presets per Voicemeeter edition,
  auto-stored under `My Documents\Voicemeeter\` — filename
  `Scene_Standard`/`Scene_Banana`/`Scene_Potato` depending on edition.
  Shown as an independent, resizable window.
- **Recall gestures** (p.47): Enter or Ctrl+Click recalls the selected
  preset; F1-F24 recall the first 24 presets directly by keyboard.
- **Right-click contextual menu, exact items** (p.47): Recall Preset
  [CTRL+CLICK], **Store Preset** (saves current Voicemeeter state into an
  empty slot or overwrites an existing one), Edit Name, Edit Comment,
  Copy Preset, Paste Preset, Load Preset..., Save Preset As..., Delete
  Preset.
- **Name/comment** (p.47): a preset can have a custom name and comment;
  if no comment is set, the slot instead displays the creation date/time.
- **Export/import** (p.47): presets can be exported/imported via
  Load/Save, or copy/paste between slots.
- **Preset scope** (p.47): a preset captures every mixing setting — all
  audio controls in the main GUI and every audio FX — but explicitly
  **not** device selection, system settings, MIDI mapping, or VBAN
  parameters.

## VAIO latency (p.48)

- **Persistent per-session latency** (p.48): VAIO latency values are
  stored as a system parameter and re-applied every time the audio
  engine (re)starts.
- **Right-click latency menu** (p.48): right-click a Virtual Input's
  caption to open it. Selectable buffer sizes (samples): 384 (3×128),
  768 (3×256), 1024, 1536 (3×512), 2048, 3072 (3×1024), 4096, 5120, 6144
  (3×2048), **7168 (default)**, 8192, 10240, 12288 (3×4096), 14336,
  16384. Also contains **Show Control Panel...** to open the VAIO
  control panel dialog.
- **Minimum-latency rule** (p.48): VAIO internal latency must not be set
  below 3x the buffer size used by the Voicemeeter audio engine and by
  applications connected to the virtual I/O.
- **7168-sample default guarantee** (p.48): expected to work reliably in
  all cases; 3072 or lower can be tried to reduce latency but isn't
  guaranteed to work on every system.
- **Latency scope** (p.48): one virtual input's latency setting applies
  to its input stream, any loopback stream, and its paired virtual output
  stream together (e.g. changing Voicemeeter Input's latency also changes
  output B1's).

## VAIO control panel (pp.48-49)

- **VAIO Control Panel dialog** (p.48-49): shows driver name/version, max
  latency, internal sample rate, current latency (editable field),
  per-I/O statistics (buffer counts, pull/push loss counters at various
  block sizes), input/output driver info (DMA size, error counts, buffer
  calls, timer glitches), a routing diagram (Input N / Output N with A/B
  cable-input selectors and a mix-down/stereo-repeat mode indicator), and
  per-channel input/output level meters (8 channels: FL FR FC LF RL RR SL
  SR) plus a Volume Control state readout.
- **Live latency editing caveat** (p.49): latency can be changed here for
  testing, with statistics shown in red if the current value is too
  small for the running stream — but the value that actually persists is
  the one set via the Voicemeeter VAIO Latency menu (p.48), since
  Voicemeeter re-applies its own stored value on every engine start.
- **8 virtual I/O couples table** (p.49): VAIO 1-5 = the VAIO extension;
  VAIO 6/7/8 map to the original Voicemeeter Input/AUX Input/VAIO3 Input
  virtual inputs and BUS B1/B2/B3 virtual outputs, respectively (a
  restatement of the p.17 table with virtual-input numbers 6/7/8
  explicit).
- **VAIO Extension mapping table** (p.49): once activated by license,
  VAIO 1-5 map to physical inputs #1-5 and physical buses A1-A5
  respectively (i.e. the extension lets an *additional* virtual capture
  point shadow each physical strip/bus).
- **VB-Audio Devices Checker app** (p.49): a bundled diagnostic listing
  every VB-Audio playback device (Voicemeeter In 1-5, Voicemeeter
  Input/AUX Input/VAIO3 Input) and every recording device (Voicemeeter
  Out A1-A6, B1-B3) with their live format (e.g. 48000 Hz, 24 bits, 2
  ch).

## VAIO loopback mode / volume control (p.50)

- **VAIO Loopback Mode** (p.50): on by default; lets a capture
  application (example given: OBS) get audio directly from a Voicemeeter
  input.
- **VAIO control panel Options menu, exact items** (p.50): Reset Pin Name
  and Icon 1, Reset Pin Name and Icon 2, Enable Windows Volume Control,
  **Enable Loopback Streaming** (checkbox, shown checked), Set Max
  Latency to 4096/5120/6144/7168/8192/12288/16384/32768 samples (each
  "requires REBOOT"), Internal Sampling Rate 44100/48000/88200/96000
  /176400/192000 Hz, Reset settings to initial state.
- **Reset Pin Name and Icon** (p.50): restores every virtual I/O's
  default name/icon, useful if they were changed or set incorrectly.
- **Admin-mode requirement** (p.50): this control-panel app must run as
  administrator to change any option, since doing so touches the system
  registry.
- **VAIO Volume Control** (p.50): "Enable Windows Volume Control" turns
  on OS-level volume control for every Voicemeeter input (every playback
  device) — if a given VAIO is also set as the Windows default playback
  device, its level becomes adjustable via the normal Windows speaker
  control. Off by default (Windows volume control has no effect on VAIOs
  until enabled here). Voicemeeter *outputs* provide no such gain
  management at all.

## VBAN overview (p.52)

- **VBAN protocol** (p.52): a simple UDP-based protocol for real-time
  digital audio transport over an IP network; designed for sending/
  receiving audio to/from any computer on a **local** network.
  VBAN-Talkie / VBAN-Receptor are companion mobile apps (iOS/Android)
  also implementing it.
- **Free/open protocol** (p.52): free to implement anywhere; the native
  PCM audio protocol, VBAN-TEXT, and VBAN-MIDI sub-protocols are all
  public, with a specification document available and third-party GitHub
  projects using it.
- **Port-sharing rule** (p.52): two applications on the same computer
  cannot share the same UDP port.

## VBAN configuration dialog (p.53)

- **Dialog fields, exact layout** (p.53): **VBAN is ON/OFF** toggle
  (enable/disable the whole VBAN service); **UDP Port** field (global,
  default 6980); **IP Host Address** display (lists the local machine's
  IP across up to its first 3 network adapters); **Main Stream
  Samplerate** display; **Reset Config / Load Config / Save Config**
  buttons; a HostName / UserName pair (for VBAN identification, editable
  by the user).
- **Incoming Streams table columns** (p.53): Stream Name, IP Address
  From, Info ("i" button), SampleRate, Ch (channel count), Format, Net
  Quality, Destination, Errors (5-segment indicator) — plus On/Off per
  row.
- **Outgoing Streams table columns** (p.53): Source (which bus feeds this
  stream), Stream Name, IP Address To, Info, SampleRate, Ch, Format, Net
  Quality, Errors — plus On/Off per row.
- **Capacity** (p.53): Banana and Potato can listen to 8 incoming streams
  (landing on any input) and send 8 outgoing streams to 8 different
  computers/devices simultaneously (each outgoing stream's source is a
  selected bus, A or B).
- **Stream parameters** (p.53): any standard sample rate 11025 Hz to
  96 kHz, 16 or 24-bit resolution, 1 to 8 channels (mono to 7.1), native
  PCM format.
- **Broadcast addressing** (p.53): a `.255` destination IP (e.g.
  `192.168.1.255`) broadcasts to every computer on that subnet — wired
  networks only, WiFi access points typically don't support broadcast.
- **Serial/ASCII incoming rows** (p.53): beyond audio, Voicemeeter also
  exposes a dedicated Serial incoming stream (for remoting via MIDI
  messages) and an ASCII incoming stream (for request-script text
  commands) in the same Incoming Streams table.
- **VBAN-MIDI outgoing** (p.53): the outgoing section can also carry a
  VBAN-MIDI stream sourced from the MIDI Mapping configuration — sending
  either all incoming MIDI or one particular MIDI source (including MIDI
  output, for MIDI feedback) across the network, so a network MIDI
  controller (via the VBAN2MIDI app) can drive Voicemeeter with both
  MIDI-in and MIDI-feedback-out.

## VBAN services / identification (p.54)

- **VBAN-Ping validation** (p.54): the "i" indicator beside an incoming
  stream's IP-Address field lights up once that connection is confirmed
  by a VBAN-Ping handshake; right-click "i" for details about the remote
  VBAN unit (hostname, application, IP, language/country, timestamp) and
  a "Resend VBAN-Ping..." action.
- **Hostname-as-address** (p.54): the IP-Address field also accepts a
  hostname directly, not just a literal IP.
- **VBAN Chat dialog** (p.54, right-click the VBAN icon to open): a basic
  text-chat service between VBAN units — lists every IP address known
  either from the VBAN configuration dialog or discovered via VBAN-Ping,
  showing every connected unit around. Sending a text message delivers it
  to every connected VBAN unit, auto-opening their chat dialog. An
  Options menu adjusts display settings and font size, and supports
  sending `<nudge>` and `<alert>` messages.
- **User identity** (p.54): a color and username, editable by the user,
  identify this instance in VBAN-Chat and VBAN-Ping responses.

## Configure VBAN audio stream (p.55)

- **Field-by-field config** (p.55): click any black field in the
  Incoming/Outgoing Streams table to edit it via an inline edit box or
  popup menu. UDP port defaults to 6980. An audio stream is uniquely
  identified by NAME + IP-ADDRESS-FROM (+ UDP port); a receiver's 3
  parameters must match the sender's exactly.
- **Per-row indicators** (p.55): a green LED beside "IP Address From"
  means audio is currently being received; a green LED beside the
  outgoing IP field means audio is currently being sent.
- **Sending an outgoing stream** (p.55): set a stream name and the target
  computer's IP address, then switch it On; its audio content comes from
  whichever bus (A or B) is selected as that row's source.
- **Receiving an incoming stream** (p.55): right-click the "Stream name"
  or "IP Address From" area to pick from currently-detected incoming
  streams directly, or edit the name/IP manually; switching a row On
  routes that stream's audio onto a virtual input strip.
- **Network Quality setting** (p.55): mainly meaningful on incoming
  streams — **Fast** assumes the network can carry audio without delay
  or loss; **Slow** trades latency for resilience on a busy/unreliable
  network where packets may arrive late or be lost more often.
- **Error LED, 5 distinct meanings** (p.55): 1. Overload (received more
  packets than expected — stream arriving too fast); 2. Corrupt (received
  corrupted packets); 3. Disorder (received out-of-order/older packets);
  4. Missing (packet loss); 5. Underrun (not enough packets received —
  stream arriving too slowly or stopped). Recommendation: if Overload/
  Underrun errors persist, switch Network Quality toward Slow.

## Additional VBAN-MIDI / command stream (p.56)

- **Dedicated MIDI/TEXT incoming rows** (p.56): two extra incoming-stream
  rows specifically for MIDI or TEXT (unlike audio streams, these don't
  require a specific "IP Address From" — an empty address field accepts
  input from *any* sender), letting Voicemeeter be remoted from multiple
  unknown sources at once. A MIDI-type row feeds Voicemeeter's own MIDI
  Mapping and is also received by the Macro Buttons app; a TEXT-type row
  shows the last received text command live in the row itself, and the
  last received MIDI message is shown similarly on the MIDI row.
- **VBAN2MIDI application** (p.56, standalone, bundled): converts a
  physical MIDI input device's stream into an outgoing VBAN stream (left
  side of its UI), and the reverse — an incoming VBAN-MIDI stream out to
  a physical MIDI output device (right side). UI fields: MIDI Input
  Device selector, MIDI Output Device selector, Outgoing VBAN Stream
  (Stream Name, IP-Address To, UDP Port, On/Off), Incoming VBAN Stream
  (Stream Name, IP-Address From, On/Off), plus an MTC (MIDI Time Code)
  readout field.

## VBAN2MIDI worked example / MIDI feedback loop (p.57)

- **Two-PC remote-MIDI-controller setup** (p.57): PC1 runs VBAN2MIDI
  connected to a physical MIDI controller, converting its output into an
  outgoing VBAN-MIDI stream to PC2's IP, and receiving an incoming
  VBAN-MIDI stream back (MIDI feedback) to drive the controller's own
  LEDs/motorized elements.
- **Mapping against the VBAN stream** (p.57): MIDI Mapping on PC2 (the
  Voicemeeter side) always operates against whichever incoming VBAN-MIDI
  stream is currently active in the VBAN dialog (matched by stream name,
  e.g. both ends named "MIDI1") — incoming messages can be learned onto a
  control there directly. Documents a **naming bug**: the MIDI Mapping
  dialog's "VBAN MIDI Input" info box is mislabeled and should read
  "VBAN MIDI Output" instead (it actually reflects Voicemeeter's own
  MIDI-feedback output over VBAN, not an input).

## Screen sharing / mirroring: VBAN-Frame (p.58)

- **VBAN-Frame protocol** (p.58): sends a video stream (screen capture)
  over the local network, alongside the audio streams — a new outgoing
  stream type. Can capture one of up to 4 connected displays, or just
  Voicemeeter's own main-window view ("app view"), to mirror it on
  another device via the companion VBAN-Screen application.
- **VBAN-Frame outgoing-stream row fields** (p.58): capture source
  (App View, or Display 1-4); frame rate (selectable 1 to 30 FPS, e.g.
  1/2/3/5/10/20/24/25/30); JPG quality percent (when JPG is the chosen
  format); image **Format** — JPG or PNG, plus a "Capture Mouse Cursor"
  toggle; and a net-quality-style bandwidth figure (default 12 Mbps,
  described as a soft target favoring the audio stream's priority, not a
  hard cap — more bandwidth is used if needed).
- **Resolution/rate limits** (p.58): up to 4K resolution per captured
  display; up to 30 frames per second.
- **Remote mouse control via VBAN-TEXT** (p.58): when the receiving
  VBAN-Screen application is displaying a VBAN-Frame stream, it can also
  send mouse events back to Voicemeeter over a VBAN-TEXT stream, letting
  Voicemeeter be controlled remotely by mouse. Enabled per incoming
  VBAN-TEXT row by right-clicking its samplerate/format field to toggle
  "Mouse Management" — an "M" indicator then shows the stream is actively
  processing mouse events.

## Screen mirroring / screen sharing details (pp.59-60)

- **App-View mirroring** (p.59): setting a VBAN-Frame outgoing stream's
  source to "App View" shares only the Voicemeeter main-window view (not
  the whole screen) via VBAN-Screen. Capture works even if the
  Voicemeeter window is hidden behind other windows or not in the
  foreground — it still captures the full main view.
- **Loopback addressing note** (p.59): destination IP `127.0.0.1` sends
  the video stream to VBAN-Screen running on the *same* PC; if
  VBAN-Screen is also on the same machine, a different UDP port than the
  audio streams should be used to avoid a port clash.
- **Recommended format for App View** (p.59): PNG, to preserve full image
  quality (App View is typically small enough that PNG's larger size
  isn't a bandwidth concern).
- **VBAN-Screen distribution** (p.59): installed with the separate
  VB-Audio Matrix package, or downloadable standalone from VB-Audio's
  VBAN web page. It is itself resizable, so it can also be used to get a
  smaller Voicemeeter view on the same or another computer.
- **Full-display sharing** (p.60): setting the source to a specific
  "Display N" instead shares that entire physical display (not just
  Voicemeeter's window) via the same VBAN-Frame mechanism. JPG is
  recommended here (over PNG) to reduce network bandwidth for a
  full-screen capture, with the JPG-quality percent field (1-100%)
  controlling the size/quality tradeoff.
