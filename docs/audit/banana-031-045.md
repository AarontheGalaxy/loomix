# Voicemeeter Banana manual, pages 31-45

## ASIO Routing Capabilities (p.31)

- **Route physical I/O to the ASIO driver on A1** (p.31): since Voicemeeter 1.0.5.0/2.0.3.0, all physical inputs and busses can be routed to up to 64 I/O of the ASIO driver selected as output A1 — the "optimal way to use Voicemeeter with a professional audio board".
- **No-device physical strip/bus routing** (p.31): selecting "no device" for a physical input or physical bus lets the System Settings dialog offer channel selection for that input/bus against the ASIO device instead. BUS A1 always uses the ASIO driver's first 8 output channels automatically; BUS A2/A3 channel ranges are chosen in System Settings ("PATCH ASIO Inputs to Strips", "PATCH BUS to A1 ASIO Outputs").
- **Buffering settings** (p.31, screenshot): separate buffer-size fields per driver type — Buffering MME (default 1024 samples), Buffering WDM (default 512 samples), Buffering KS (default 512 samples), Buffering ASIO (default: ASIO preferred size); per-output added delay fields OUT A1/A2/A3 (ms, default 0ms each).
- **Virtual ASIO Type** (p.31, screenshot): a selectable format, e.g. "Float32LSB".
- **WDM Input Exclusive Mode** (p.31, screenshot): Yes/No toggle.
- **Preferred Main SampleRate** (p.31, screenshot): e.g. 44100 Hz.
- **Engine Mode** (p.31, screenshot): e.g. "Normal" (implies other modes selectable, not enumerated on this page).
- **ASIO output-channel overwrite warning** (p.31): bus outputs are copied into ASIO output channels in logical order A1, A2, A3 — if A2's assigned channels overlap A1's, A2 silently overwrites A1's audio on that channel.

## Integrated Recorder (p.32-33)

- **Player/recorder transport** (p.32): plays back WAV, AIFF, MP3, M4A, MP4, MOV, AVI, WMA, WMV; records to WAV, BWF, AIFF, or MP3.
- **Transport controls** (p.32, screenshot): REW, FF, Play, Stop, Record/Pause buttons; a progress bar (click to seek); current input level meter; current filename/directory display; sound format readout (e.g. "44100 Hz, 2 Ch"); elapsed time and "Remain" time readouts.
- **Per-bus playback routing** (p.32): A1-A3/B1-B2 buttons on the recorder route playback output to those busses, same as a strip.
- **Currently armed strip/bus indicator** (p.32): shown on the recorder UI.
- **Auto-generated recording filename** (p.32): pattern `Record <date> at <time>.wav`, e.g. `Record 2015-01-02 at 11h23m24s.wav`, saved to the user's Documents/Voicemeeter folder by default.
- **Recorder Options dialog** (p.32-33): opened by right-clicking the tape deck.
  - **PRE-FADER INPUTS arming** (p.32-33): per-source toggle row — Physical Input #1/#2/#3, Virtual Input, Virtual AUX — "Arm Inputs To Record". Records one or all inputs in stereo (mixed together), independent of fader gain, mute, solo, and FX state — i.e. the original incoming signal at its original gain, all armed sources summed together.
  - **POST-FADER OUTPUTS arming** (p.32-33): per-bus toggle row — Physical BUS A1/A2/A3, Virtual BUS B1/B2 — "Record BUS Outputs (single BUS)". Records what you actually hear on the selected bus (2 to 8 channels, works with Composite mode); a bus doesn't need to be connected to a real device to be used purely as a recording source.
  - **Target Directory** (p.32-33): text field, click to browse/select.
  - **Prefix Name** (p.32-33): text field for the filename prefix (defaults to "Record" if left blank).
  - **Pre Recording Time** (p.32-33): 0 to 20 seconds max; Voicemeeter is permanently recording into a rolling buffer at this size, and starting a real recording prepends this pre-roll to the start of the file (0 = no pre-recording buffer).
  - **File Type** (p.32-33): WAV, BWF, AIFF, or MP3 (32 to 320 kbps). MP3 is stereo-only; the others support up to 8 channels when recording a bus.
  - **Sample Rate** (p.32-33): e.g. 48000 Hz — set independently of Voicemeeter's own running engine sample rate (example given: file recorded at 48kHz while Voicemeeter runs at 44.1kHz).
  - **Bit Resolution** (p.32-33): e.g. 16 Bits.
  - **Channels** (p.32-33): e.g. 2.
  - **Bit Rate** (p.32-33): e.g. 320 kbps (for MP3).
  - **MULTITRACK OPTION** (p.32-33): Yes/No. If Yes, generates one additional file per track/channel, filename suffixed `_Track1`, `_Track2`, etc. per the channel count in the file format ("Generates 2 Mono BWF files" example shown for a 2-channel setup).
  - **Play On Load** (p.32-33): Yes/No — auto-plays a file immediately after it's selected.
  - **Loop** (p.32-33): Yes/No — loops playback continuously.
  - **Playback Gain** (p.32-33): a slider controlling the gain of the file being played back.
  - **Stop Record: After Duration** (p.32-33): a timer that auto-stops recording after a set duration; `00:00:00` disables it. Practical for recording a movie or podcast of known length.

## Other Voicemeeter Tools & Accessories (p.35)

- **8x8 Gain Matrix** (p.35): companion app (separate from Voicemeeter itself), a single 8x8 gain matrix applicable to the selected bus, for redistributing audio channels across different multichannel speaker setups; developed against the Voicemeeter Remote API SDK.
- **15 Bands graphic EQ** (p.35): companion app, a 15-band graphic EQ applicable to a selected bus, stereo only; for adjusting a P.A. system's sound.
- **VBAN2MIDI** (p.35): standalone app to send a VBAN-MIDI stream from a physical MIDI input device, or send incoming VBAN-MIDI stream data to a physical MIDI output. Warning: two applications cannot use the same UDP port at the same time.

## Preset Scene (p.36)

- **Preset list** (p.36): 64 presets per Voicemeeter edition, auto-stored under My Documents\Voicemeeter, one file set per edition ("Scene_Standard", "Scene_Banana", "Scene_Potato").
- **Voicemeeter Scene window** (p.36): an independent, resizable window listing presets with name and a date/time stamp.
- **Recall a preset** (p.36): Enter key, or Ctrl+Click; F1-F24 keys recall the first 24 presets directly.
- **Store/manage a preset** (p.36, right-click context menu): Recall Preset [Ctrl+Click], Store Preset, Edit Name, Edit Comment, Copy Preset, Paste Preset, Load Preset..., Save Preset As..., Delete Preset.
- **Preset name/comment** (p.36): user-definable; if no comment is set, the creation date/time is shown instead.
- **Preset export/import** (p.36): via Load/Save, or copy/paste.
- **Preset scope** (p.36): contains all mixing settings — every audio control in the main Voicemeeter GUI plus audio FX. Presets do **not** contain device selection, system settings, MIDI, or VBAN parameters.

## VAIO Latency (p.37-38)

- **VAIO latency setting** (p.37): right-click a Virtual Input's caption to open the latency menu; stored as a system parameter and recalled on every Audio Engine start.
- **Latency options (samples)** (p.37, screenshot menu): 384 (3x128), 768 (3x256), 1024, 1536 (3x512), 2048, 3072 (3x1024), 4096, 5120, 6144 (3x2048), 7168 (Default), 8192, 10240, 12288 (3x4096), 14336, 16384.
- **Latency constraint** (p.37): must not be below 3x the buffer size used by the Voicemeeter Audio Engine and the applications connected to that Virtual I/O; latency applies uniformly to the virtual input stream, its possible loopback stream, and the virtual output stream — changing latency for a Voicemeeter input changes it for the paired output (e.g. B1) too.
- **"Show Control Panel..." menu item** (p.37): opens the VAIO Control Panel.
- **VAIO Control Panel window** (p.37-38): shows driver name/version, max latency, internal sample rate, per-I/O statistics (buffer counts at various block sizes, pull/push loss counters, timer glitch counts), input/output level meters per channel (FL/FR/FC/LF/RL/RR/SL/SR), current Mode (e.g. "Virtual I/O"), and Volume Control status (Enabled/Disabled).
- **VAIO couples table** (p.38): the new driver offers 8 I/O couples; VAIO 6/7/8 map to the base set (VAIO in 6 = Voicemeeter input / VAIO out 6 = Voicemeeter BUS B1; VAIO in 7 = Voicemeeter AUX input / VAIO out 7 = Voicemeeter BUS B2; VAIO 8 unused by default).
- **VAIO Extension table** (p.38): if licensed, VAIO 1-3 map to Voicemeeter input #1/#2/#3 and BUS A1/A2/A3; VAIO 4-5 unused.
- **VB-Audio Devices Checker tool** (p.38, screenshot): lists all Playback Devices and Recording Devices (VB-Audio driver only) with format detail (e.g. "48000 Hz, 24 bits, 2 Ch (48000 Hz, 32 bits, 2 Ch)").

## VAIO Loopback Mode / Volume Control (p.39)

- **VAIO Loopback Mode** (p.39): active by default; lets capture applications (e.g. OBS) get audio from the Voicemeeter input directly. Toggled via "Enable Loopback Streaming" in the VAIO Control Panel's Options menu.
- **VAIO Control Panel Options menu** (p.39, screenshot): Reset Pin Name and Icon 1, Reset Pin Name and Icon 2, Enable Windows Volume Control, Enable Loopback Streaming [checked by default], Set Max Latency: 4096/5120/6144/7168/8192/12288/16384/32768 smp (each "requires REBOOT"), Internal Sampling Rate: 44100/48000/88200/96000/176400/192000 Hz, Reset settings to initial state.
- **Admin mode requirement** (p.39): the VAIO Control Panel app must run in administrator mode to change options that touch the system registry.
- **"Enable Windows Volume Control"** (p.39): off by default (Windows volume control has no effect on Voicemeeter VAIO playback-device inputs); enabling it lets the OS's own speaker/volume control adjust that VAIO's level if it's set as the default playback device. Voicemeeter *outputs* provide no such gain management.

## VBAN: VB-Audio Network (p.40-45)

- **VBAN protocol** (p.41): a simple UDP-based protocol for real-time digital audio transport on a local IP network. Free/public to implement; PCM native audio, VBAN-TEXT, and VBAN-MIDI protocols are all public, spec available from the vendor support page.
- **VBAN-Talkie / VBAN-Receptor** (p.41): companion mobile apps (iOS/Android) implementing VBAN to send/receive audio to/from Voicemeeter.
- **VBAN icon / configuration dialog** (p.41): click to open; configure incoming stream(s) (audio from other computers) and outgoing stream(s) (audio sent to other computers).
- **VBAN ON/OFF** (p.42): enable/disable the VBAN service globally.
- **Global UDP port** (p.42): default 6980.
- **IP Host Address display** (p.42): lists this machine's IP address(es), for up to the first 3 possible network adapters.
- **Main Stream Samplerate** (p.42): e.g. 44100 Hz.
- **Reset/Load/Save Config buttons** (p.42): manage the VBAN configuration as a whole.
- **Incoming Streams table** (p.42): per-row On/Off toggle, Stream Name, IP Address From, an info ("i") indicator, SamplerRate, Ch(annel count), Format (e.g. "PCM 16 bits"), Net Quality, Destination (e.g. "In #3", "In #5"), and an Errors indicator row of lights.
- **Outgoing Streams table** (p.42): per-row On/Off, Source (a bus, e.g. "BUS A1"), Stream Name, IP Address To, SamplerRate, Ch, Format, Net Quality, Errors.
- **Stream capacity** (p.42): Banana and Potato can listen to 8 incoming streams (on any input) and send 8 outgoing streams to 8 different computers/devices; outgoing audio source is whichever bus is selected.
- **VBAN stream parameters** (p.42): sample rate 11025 Hz to 96 kHz, 16 or 24 bit resolution, 1 to 8 channels (mono to 7.1).
- **Broadcast addressing** (p.42): using a `.255` broadcast IP address sends a stream to every computer on that subnet — wired networks only, most WiFi APs don't support broadcast.
- **VBAN-Serial / VBAN-ASCII streams** (p.42): VBAN can also transport MIDI messages and text/request-script commands to remotely control Voicemeeter; dedicated "Serial" and "ASCII" incoming stream rows exist for this alongside the audio stream rows.
- **VBAN identification / VBAN-Chat** (p.42): a USER NAME and a color can be set for identification purposes.
- **VBAN-MIDI outgoing stream** (p.42): can carry MIDI sourced from the MIDI-Mapping feature — either all incoming MIDI or one particular MIDI source (including MIDI Feedback output) — over the network; usable with a networked MIDI controller via the VBAN2MIDI app.
- **VBAN-PING identification** (p.43): the "i" indicator next to an incoming stream's IP-Address field highlights when the connection is validated by a VBAN-Ping handshake; right-click "i" for details about the remote VBAN unit (hostname, IP, application name, language/country, timestamp, and a "Resend VBAN-Ping..." action).
- **IP-Address field accepts hostname** (p.43): as an alternative to a literal IP address.
- **VBAN-Chat dialog** (p.43): opened by right-clicking the VBAN icon. Basic chat between VBAN units; lists all IP addresses from the config dialog plus any identified via VBAN-Ping. Sending a TEXT message pops the VBAN-Chat dialog on every connected unit automatically. An Options menu controls display options and font size; supports sending `<nudge>` and `<alert>` special messages.
- **Configure VBAN audio stream fields** (p.44): click any black field to edit. An audio stream is uniquely defined by its Name, IP-Address-From, and UDP port — all three must match on both ends to receive a stream. Fields per row: Activate/Disable toggle, Stream Name, IP Address, Port (default 6980), Current Audio Format (Samplerate, e.g. 11025-96kHz; Channels, 1-8; Format, 16/24-bit PCM), Network Capabilities/Quality, Input Selection/Destination. Green LED = audio being received (incoming) / sent (outgoing).
- **Send outgoing stream** (p.44): define stream name and destination IP, switch it on; the audio source sent is whichever bus (A or B) was selected for that stream.
- **Receive incoming stream** (p.44): right-click "Stream name" or "IP Address From" to pick from currently detected incoming streams, or edit manually; switch the stream on to route its audio to the assigned virtual input strip.
- **Network Quality setting** (p.44): FAST (no added delay/error correction, needs a good network) vs SLOW (for busy/unreliable networks, tolerates delayed/lost packets) — most useful on incoming streams.
- **Error LED meanings** (p.44): 1 Overload (receiving packets too fast), 2 Corrupt (corrupted packets received), 3 Disorder (packets received out of order/older), 4 Missing (packets lost), 5 Underrun (not enough packets received — stream arriving too slow or stopped). Recommendation: switch Network Quality toward SLOW if overload/underrun errors persist.
- **VBAN-MIDI / Command stream rows** (p.45): incoming-stream rows can also be typed as MIDI (shown as e.g. "115200 bps Serial") or TEXT/command (e.g. "256000 bps UTF8") instead of audio; these don't require an "IP Address From" match — they accept a message from anywhere ("No address = any"). The MIDI stream row shows the last received MIDI message; the Command row shows the last received TEXT command (e.g. `strip[0].mute=1;strip[1].mute=1;strip[2].mute=`). Both are also receivable by the MacroButtons application.
- **VBAN2MIDI application detail** (p.45): standalone app converting a physical MIDI input device to an outgoing VBAN stream (left side) and an incoming VBAN-MIDI stream to a physical MIDI output device (right side); fields: MIDI Input Device, MIDI Output Device, Outgoing VBAN Stream (Stream Name, IP-Address To, UDP Port, On/Off), Incoming VBAN Stream (Stream Name, IP-Address From, On/Off), an MTC (MIDI Time Code) readout field. Usable to bridge a MIDI controller on a second PC to Voicemeeter's MIDI mapping over the network.
