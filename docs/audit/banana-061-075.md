# Voicemeeter Banana manual, pages 61-75

## Button command for button interactions (p.61)

- **Button(N).State** (p.61): sets another button's pushed/released state remotely, e.g. `Button(5).State = 1;` (push button ID 5), `Button(5).State = 0;` (release it).
- **Button(N).StateOnly** (p.61): `Button(5).StateOnly = 1;` sets the button's visual/logical state without firing its associated request script.
- **Button.State (no index) in INIT script only** (p.61): `Button.State = 0;` changes the state of the *current* button — only valid inside that button's own initial-state script.
- **Button(N).Trigger** (p.61): enables/disables the Audio Trigger option on a given button remotely, e.g. `Button(5).Trigger = 1;` / `= 0;`.

## Wait command (p.61)

- **Wait(ms)** (p.61, added September 2019): introduces a timed pause between requests within one script, to build a sequence, e.g. fading a strip down, waiting 2 seconds, fading back up 1 second later — `Strip(0).gain=-12.0; Wait(2000); Strip(0).gain=0.0; Wait(1000); Strip(0).FadeTo=(-10.0,1000); Wait(1000); Strip(0).FadeTo=(0.0,1000);`.

## Load Button map (p.61)

- **Load("filename")** (p.61, added "Mars 2020" version): lets a button load a different Button Map (MacroButtons config file) previously saved via the MacroButtons system menu's Save function.

## Show command (p.61)

- **Show(0) / Show(1)** (p.61, added October 2021): hides (0) or shows (1) the MacroButtons application window itself. Warning: a script that hides the app should also implement a way to show it again, or it becomes inaccessible.

- **MIDI Source bit combination** (p.62): `vban.outstream[i].route`'s MIDI-source variant is a bitmask: MIDI Input = 0x01, MIDI Aux input = 0x02, VBAN IN = 0x04, MIDI OUT = 0x08. Example: ALL MIDI IN = 0x01+0x02+0x04 = 7.
- **Parameters that force an Audio Engine restart when changed** (p.62): `vban.Enable`, `vban.instream[i].port`, `vban.instream[i].quality`, `vban.outstream[i].quality`.
- **VBAN SampleRate allowed values** (p.62): 11025, 16000, 22050, 24000, 32000, 44100, 48000, 64000, 88200, 96000 Hz.
- **VBAN Quality levels** (p.63): 0 (Optimal), 1 (Fast), 2 (Medium), 3 (Slow), 4 (very slow). Trades internal stack size (and latency) for stream stability against network instability; Optimal assumes a regular, real-time-capable network, very slow assumes timing problems/unexpected waits. More relevant on the receiver side; the transmitter is expected to always run Optimal.
- **VBAN Bit Resolution / data format** (p.63): 1 (16-bit PCM) or 2 (24-bit PCM).

## AUTO Ducking / TRIGGER (p.63-65)

- **TRIGGER mechanism for auto ducking** (p.63): lets a button's ON/OFF requests fire automatically based on an input level, rather than a manual push — usable to control any parameter or function (e.g. the REC button) from an input level. Example given: a "Ducking" button with Strip selector "in #1" (the microphone), In threshold -15.7dB, Out threshold -35.4dB, Hold 100ms; ON-trigger script fades the music strip (Strip[3]) to -15dB and its EQ mid-band to -12dB when mic level crosses -15dB, OFF-trigger script fades it back to 0dB/0dB.
- **TRIGGER threshold cursors** (p.64): green cursor = IN threshold (level to exceed to fire trigger-in); red cursor = OUT threshold (level to fall below to fire trigger-out).
- **HOLD parameter** (p.64): minimum time in ms the trigger stays open/engaged once fired.
- **Trigger source options** (p.64): dependent on an input Strip level (in #1 to in #8) or an output BUS level (out #1 to out #8).
- **Trigger Input Mode (3 options)** (p.64): Pre-Fader, Post-Fader (pending on slider gain), or Post-Mute (pending on the mute button's state) — determines which stage of the signal chain the trigger measures level from.
- **Trigger "Level Option: After Mute"** (p.69/74 screenshots, related field): an additional checkbox seen alongside Strip/In/Out/Hold fields in later dialog versions.

## HID Manager (p.65)

- **HID Device Button configuration** (p.65): lets a macro button connect directly to any HID (Human Interface Device), for controlling/managing special devices and keys not available via the normal Keyboard Shortcut list.
- **HID Configuration dialog** (p.65): "Select HID Device to configure" dropdown; HID Name field (editable friendly name); Status indicator (e.g. "Status:Connected"); Control Code field (the detected bit/code, e.g. "Bit 26 = 1"); HID Button Name field; a "HID Current Data" readout box showing raw HID report bytes when the physical key/button is pressed; a "Learn" checkbox to enter detection mode.
- **HID learn workflow** (p.65): select the device, press the physical key to detect it (raw HID data shown live), assign a friendly device name and button name, click OK twice (HID dialog, then Button Configuration) to confirm.
- **HID Manager also covers regular keyboard/mouse** (p.65): useful for special keys not present in the standard Keyboard Shortcut list.

## GPIO (p.66)

- **GPIO combo box** (p.66): selects one of 16 GPI (general purpose input) lines provided by an extra USB hardware module called "GPI8-USB".
- **GPI8-USB module** (p.66): a DB9-connector USB module; the DB9 connector supports 8 simple electric switches, a foot pedal, or anything able to create an electric contact; a second DB9 connector can be added for lines 9-16. Purchasable via the vendor website.

## System Functions — sending commands to Windows (p.67-68)

- **Overview** (p.67): MacroButtons can send Keyboard Events or run command-line programs via special function-call-style instructions inserted into a button's request script, alongside ordinary Voicemeeter parameter requests. Trigger sources for a button: mouse click, single key or key combination (e.g. Shift+A), MIDI event, GamePad, HID device, or a Voicemeeter input-level Trigger.
- **System.KeyDown("Key") / System.KeyUp("Key")** (p.67): String parameter; press/release a key combination.
- **System.KeyPress("Key")** (p.67): String; sends Key Down + Key Up in one call.
- **System.SetFocus("ApplicationName")** (p.67): String; sets keyboard focus to a named application.
- **System.ResetFocus()** (p.67): no parameter; resets keyboard focus (auto-sent at the end of a script).
- **System.Mouse("Action")** (p.67): String; one of LBUTTONDOWN, LBUTTONUP, RBUTTONDOWN, RBUTTONUP, MBUTTONDOWN, MBUTTONUP. Example: `System.Mouse("LBUTTONDOWN");`. These System.* commands are not sent to Voicemeeter itself (they act on the OS).
- **System.Execute(exe, dir, arg)** (p.67-68): Strings; works like Windows' `CreateProcess`/`ShellExecute`, launching any application with command-line arguments. Full signature `System.Execute(szprogram, szworkdir, szcommand)`. Example: opening a URL in Internet Explorer, `System.Execute("C:\Program Files\Internet Explorer\iexplore.exe", "", "-new www.voicemeeter.com");`.
- **Escaping special characters** (p.68): `%'` (percent + single-quote) inserts a literal double-quote `"`; doubling a percent char `%%` inserts a single literal `%`.
- **Environment variables** (p.68): `%envname%` syntax, e.g. `System.Execute("%windir%\write.exe","%TMP%","");` to launch Notepad-equivalent WRITE editor.
- **Running a DOS/console application** (p.68): must launch `cmd.exe` with `/K` (keep window open, carry out command but remain) or `/C` (carry out command then terminate) to run a command line. Example: `System.Execute("%windir%\system32\cmd.exe","%windir%\system32","/K ipconfig");`; another example pings a router at 192.168.1.1 via `/K ping 192.168.1.1`.
- **System.KeyDown/KeyUp examples** (p.68): combination strings like `"A"`, `"SHIFT+T"`, `"CTRL+NP1"`, `"ALT+F8"` (NP1 = numpad 1). `System.KeyPress` sends both Down and Up for a given combination in one call.

## Send M.I.D.I. Message (p.69-70)

- **2x MIDI output devices** (p.69, since MacroButtons 1.0.1.1): configurable via the app's system menu — "MIDI OUT1 device" / "MIDI OUT2 device" submenus each listing detected MIDI devices (or "- No Midi -").
- **System.SendMidi("outN", type, ...)** (p.69-70): 4 request types, channel range 1 to 16: `System.SendMidi("out1","note-on",channel,note,velocity);`, `"note-off"` (same args), `"ctrl-change",channel,ctrl,value`, `"prg-change",channel,nPrg`.
- **RAW DATA MIDI function** (p.70): `System.SendMidi("out1","data",aa,bb,cc,ee,ff,gg,...);` sends any raw MIDI message including sys-ex; values for this variant only are in hexadecimal (00 to FF), whereas the typed note/ctrl/prg functions use decimal (0-127) values.
- **SendMidi without "System." prefix** (p.70, since October 2020): `SendMidi("out1", ...)` works identically, dropping the "System." prefix.

## Send VBAN-MIDI or VBAN-TEXT / VBAN2MIDI (p.71-73)

- **VBAN-MIDI / VBAN-TEXT via script** (p.71, since Voicemeeter 1.0.3.5/2.0.3.5): MIDI messages can be sent over VBAN-MIDI, and Voicemeeter script commands over VBAN-TEXT; MacroButtons can also learn MIDI codes arriving via an incoming VBAN-MIDI stream. The bundled MIDI2VBAN/VBAN2MIDI app converts a physical MIDI I/O device to/from a VBAN-MIDI stream.
- **MacroButtons can be driven by an Xbox-style gamepad** (p.71): shown as one of the trigger source options alongside MIDI controllers.
- **VBAN Configuration dialog in MacroButtons** (p.71, system menu item "VBAN Configuration..."): configures up to 2 VBAN-MIDI output streams and 4 VBAN-TEXT output streams, each with On toggle, Stream Name, IP Address To, UDP port (default 6980).
- **VBAN-FRAME output stream (GUI capture) in MacroButtons** (p.71): lets MacroButtons share its own graphic interface to another device via VBAN-Frame, with a stream name/IP/port row, plus a separate "Incoming Command (Mouse)" row (On toggle, IP Address From, UDP port) to receive VBAN-Screen mouse commands for remote control.
- **MacroButtons system menu (fuller list)** (p.72, screenshot): Restore, Move, Size, Minimize, Maximize, Close [Alt+F4], Restart Engines, New Button Map, Load Button Map, Save Button Map, System Tray (Close = Hide), Run on Windows Startup, Show App On Startup, Always Visible, Store Last Buttons State, MIDI OUT1 device, MIDI OUT2 device, VBAN Configuration..., DMX Configuration..., GPIO Configuration..., Restart HID Manager, About / License..., Online Help / Support..., Shut Down Macro Buttons (Q).
- **System.SendMidi via VBAN** (p.72): same 4 request types as physical MIDI out, but targeting a VBAN stream name, e.g. `System.SendMidi("vban1","note-on",channel,note,velocity);`; also supports the raw `"data"` variant.
- **Send Voicemeeter TEXT request through VBAN stream** (p.72-73): a command script is wrapped in `BEGIN_SECTION("vban1") ... END_SECTION` to route it out over that named VBAN-TEXT stream, e.g. muting two strips and setting a bus gain, sent to whichever VBAN stream is named "vban1"/"vban2" etc. in the VBAN Configuration dialog.
- **SendText(...) function-call syntax** (p.73): an alternative syntax matching the VBAN-Button Android app's convention: `SendText("vban2",Strip(0).mute=1; Strip(1).mute=1;Bus(0).gain=0.0;);` — can also be split across multiple lines, with the final closing parenthesis ending the whole request.

## DMX-512 lighting control (p.74)

- **DMX 512 support** (p.74, since MacroButtons 1.0.2.7): sends DMX-512 requests through a DMX serial (COM) interface selected in a "DMX configuration" dialog in the MacroButtons system menu.
- **System.DMXSetValue(addr, channel, value)** (p.74): sets one DMX value at a given device address and channel.
- **System.DMXSetValue(addr, channel, value1, value2, value3, value4...)** (p.74): variant that fills several consecutive channels at once from a single call.
- **System.DMXCommit()** (p.74): sends the newly modified DMX frame out over the interface.
- **Tested hardware example** (p.74): Enttec Open DMX USB Interface.

## Voicemeeter Remote API (for developer only) (p.75)

- **VoicemeeterRemote.dll (VBVMR-API)** (p.75): the underlying API the request-script mechanism above is built on; usable by any third-party application in any language. Documented entry points include `Login()`, `Logout()`, `GetVoicemeeterType()`, `GetVoicemeeterVersion()`, `IsParametersDirty()`, `GetParameterFloat()`, `GetParameterStringA()`, `GetParameterStringW()`, `SetParameterFloat()`, etc. Up to 4 client applications can remote a Voicemeeter/Banana instance simultaneously.
- **AUDIO API (since Voicemeeter 1.0.5.0/2.0.3.0)** (p.75): lets a client process audio *inside* Voicemeeter at 3 distinct callback points: (1) **Audio Callback IN** — pre-strip input insert, 22x inputs/22x outputs (channel in/out); (2) **Audio Callback OUT** — pre-master bus insert, 40x inputs/40x outputs; (3) **Audio Callback MAIN** — the main driver point, 22x inputs/40x inputs and outputs. SDK downloadable from the vendor forum.
