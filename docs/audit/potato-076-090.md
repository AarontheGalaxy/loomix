# Voicemeeter Potato manual, pages 76-90

## Trigger detail, continued (p.76)

- **Bus-level trigger source** (p.76): a button's audio Trigger (p.64,
  75) can be driven from an input strip's level (`in #1` to `in #8`) *or*
  from an output bus's level (`out #1` to `out #8`) — not strip-only.
- **Input Mode, 3 options** (p.76): when the trigger source is an input
  strip, its level can be read **Pre-Fader**, **Post-Fader** (depends on
  the strip's slider gain), or **Post-Mute** (depends on the mute
  button's state).

## HID Manager (p.77)

- **HID Device Button config** (p.77): lets a Macro Button bind directly
  to any HID device, useful for special/unusual devices and keys.
- **HID Configuration dialog fields** (p.77): Select HID Device
  (dropdown of detected HID devices with their VID/PID); HID Name (a
  friendly name field); Status (Connected/Disconnected indicator);
  Control Code (e.g. shown as `Bit 26 = 1`); HID Button Name; HID Current
  Data (a live readout of the raw HID report bytes received while
  pressing the device's key/button); a **Learn** checkbox to auto-detect
  the control code (and optionally name it) from the next physical key
  press.
- **Confirmation flow** (p.77): click OK on the HID dialog to confirm the
  HID binding, then OK again on the Button Configuration dialog to
  finalize.
- **Regular keyboard/mouse via HID** (p.77): the HID manager can also
  bind ordinary keyboard/mouse input, useful for special keys not present
  in the standard Keyboard Shortcut dropdown list.

## GPIO (p.78)

- **GPIO combo box** (p.78): selects one of 16 GPI (general-purpose
  input) lines provided by a separate USB accessory, the "GPI8-USB"
  module.
- **DB9 wiring** (p.78): one DB9 connector wires up to 8 simple electric
  switches, a foot pedal, or anything else that can create an electrical
  contact; a second DB9 connector extends this to lines 9-16 (16 total).
  Sold separately via vb-audio.com.

## System Functions: Windows-level commands (pp.79-80)

Exact table (these act on the OS directly, **not** sent to Voicemeeter
itself):

| Function | Value type | Remark | Ver. |
|---|---|---|---|
| `System.KeyDown("Key")` | string | | 1 |
| `System.KeyUp("Key")` | string | | 1 |
| `System.KeyPress("Key")` | string | sends Key Down + Key Up together | 1 |
| `System.SetFocus("ApplicationName")` | string | sets keyboard focus | (n/a) |
| `System.ResetFocus()` | — | resets keyboard focus | (n/a) |
| `System.Mouse("Action")` | string | `LBUTTONDOWN`, `LBUTTONUP`, `RBUTTONDOWN`, `RBUTTONUP`, `MBUTTONDOWN`, `MBUTTONUP` | 1 |
| `System.Execute(exe, dir, arg)` | strings | | 1 |

- **System.Execute semantics** (p.79-80): behaves like Windows'
  `CreateProcess`/`ShellExecute` — launches any program with a
  command-line argument. Example (open a URL in Internet Explorer):
  `System.Execute("C:\Program Files\Internet Explorer\iexplore.exe",
  "", "-new www.voicemeeter.com");`.
- **Escaping** (p.80): a double quote inside an argument string is
  written as `%'` (percent + single quote); a literal percent sign is
  written doubled, `%%`.
- **Environment variables** (p.80): `%envname%` syntax is usable inside
  `System.Execute` arguments — example, launching Notepad-like WRITE:
  `System.Execute("%windir%\write.exe","%TMP%","");`.
- **Running a DOS/console command** (p.80): launch `cmd.exe` with `/K`
  (keep window open after running) or `/C` (run then terminate) —
  example, `ipconfig`: `System.Execute("%windir%\system32\cmd.exe",
  "%windir%\system32","/K ipconfig");`; another example pings a router at
  `192.168.1.1`.
- **KeyDown/KeyUp/KeyPress syntax** (p.80): a string of 1-4 keys, e.g.
  `"CTRL+SHIFT+F10"` or just `"0"`. Examples: `System.KeyDown("A");`,
  `System.KeyDown("SHIFT+T");` (paired with matching `KeyUp` calls);
  `System.KeyPress("CTRL+NP1");` sends both halves in one call.

## Send MIDI message (p.81-82)

- **2 MIDI output devices** (p.81, Macro Buttons 1.0.1.1+): selectable
  as "out1"/"out2" via the app's own menu (**MIDI OUT1 device**,
  **MIDI OUT2 device** submenus, each listing detected MIDI devices, or
  "- No Midi -"). Macro Buttons app menu, exact items shown: New Button
  Map, Load Button Map, Save Button Map, System Tray (Close = Hide), Run
  on Windows Startup, Show App On Startup, Always Visible, MIDI OUT1
  device, MIDI OUT2 device, Shut Down Macro Buttons.
- **4 request types** (p.81-82), channel 1-16: `System.SendMidi("out1",
  "note-on", channel, note, velocity);`, `"note-off"`, `"ctrl-change"`
  (with `ctrl, value`), `"prg-change"` (with `nPrg`).
- **Raw MIDI data function** (p.82): `System.SendMidi("out1", "data",
  aa, bb, cc, ee, ff, gg, ...);` — sends any MIDI message including
  sys-ex; values in this function only are hexadecimal (00-FF), unlike
  every other MIDI function's decimal (0-127) values.
- **Prefix-free syntax** (p.82, Oct 2020+): `SendMidi(...)` works
  identically without the `System.` prefix.
- **"Level Option" / "After Mute" trigger field** (p.82): the Trigger
  section's dialog now shows an additional **Level Option** dropdown
  beside Hold, and an **After Mute** checkbox — present in this
  screenshot but not further explained textually here or elsewhere in
  the pages read so far; likely gates whether the level trigger is
  evaluated relative to the strip's mute state.

## Send VBAN-MIDI / VBAN-TEXT (pp.83-85)

- **VBAN-MIDI / VBAN-TEXT scripting** (p.83, Voicemeeter 1.0.3.5/2.0.3.5+):
  Macro Buttons can send MIDI via VBAN-MIDI and a Voicemeeter script via
  VBAN-TEXT; it can also learn a MIDI code arriving over an incoming
  VBAN-MIDI stream. A bundled app (named "MIDI2VBAN" in this section's
  diagram, elsewhere in the manual called VBAN2MIDI) converts physical
  MIDI I/O to/from a VBAN-MIDI stream.
- **Sharing the Macro Buttons GUI itself** (p.83): via VBAN-Frame to a
  VBAN-Screen application on another device; drawing commands can also
  be sent to VBAN-Screen over VBAN-TEXT.
- **VBAN output setup, in Macro Buttons' own menu** (p.84): the VBAN
  Configuration dialog there configures **2 VBAN-MIDI output streams**
  and **4 VBAN-TEXT output streams**. Full Macro Buttons system-menu
  item list confirmed: Restart Engines, New Button Map, Load Button Map,
  Save Button Map, System Tray (Close = Hide), Run on Windows Startup,
  Show App On Startup, Always Visible, **Store Last Buttons State**
  (checkbox), MIDI OUT1 device, MIDI OUT2 device, **VBAN
  Configuration...**, **DMX Configuration...**, **GPIO
  Configuration...**, **Restart HID Manager**, About/License..., Online
  Help/Support..., Shut Down Macro Buttons (with a `(Q)` shortcut hint).
- **VBAN Configuration dialog rows** (p.84): VBAN-MIDI output Streams
  (2 rows, "MIDI1"/"MIDI2", each with On/Stream Name/IP Address To/UDP
  port); VBAN-TEXT output Streams (4 rows, "Command1"-"Command4", same
  fields); **VBAN-FRAME output Streams (GUI Capture)** (1 row, "MBGUI" —
  shares the Macro Buttons window itself); **Incoming Command (Mouse)**
  (1 row, "Command1", with an "IP Address From" field instead of To —
  receives remote-mouse commands from a VBAN-Screen viewer).
- **Sending MIDI via a VBAN stream** (p.84): once configured, the same
  `SendMidi` instruction just targets `"vban1"`/`"vban2"` instead of
  `"out1"`/`"out2"`: `System.SendMidi("vban1", "note-on", channel, note,
  velocity);`; the raw-data form works the same way.
- **Sending a Voicemeeter script via VBAN-TEXT** (pp.84-85): wrap the
  script in a named section block: `BEGIN_SECTION("vban1") ... 
  END_SECTION` sends everything inside through the VBAN1 TEXT stream;
  `BEGIN_SECTION("vban2")` targets VBAN2 instead.
- **Function-style alternative syntax** (p.85, to match the VBAN-Button
  Android app's own syntax): `SendText("vban2", Strip(0).mute=1;
  Strip(1).mute=1; Bus(0).gain= 0.0;);` — can also be split across
  multiple lines, with the final closing parenthesis ending the whole
  request.
- **VBAN-TEXT stream naming confirmed** (p.85): the 4 VBAN-TEXT output
  rows (Command1-4) map to script-target names `"vban1"`-`"vban4"`
  respectively — a separate numbering namespace from the 2 VBAN-MIDI
  rows, which *also* use `"vban1"`/`"vban2"` for MIDI purposes. The
  manual does not flag this dual reuse of "vban1"/"vban2" as a naming
  collision, but it's worth noting: the same literal string means "MIDI1
  stream" in a `SendMidi` call and "Command1/TEXT stream" in a
  `SendText`/`BEGIN_SECTION` call — disambiguated only by which function
  is being called, not by the name itself.

## DMX 512 lighting control (p.86)

- **DMX 512 via Macro Buttons** (p.86, 1.0.2.7+): sends DMX-512 requests
  through a DMX serial (COM) interface, selected in a DMX configuration
  dialog in Macro Buttons' system menu.
- **`System.DMXSetValue(addr, channel, value)`** (p.86): sets one DMX
  channel's value on a given device address.
- **Multi-channel variant** (p.86): `System.DMXSetValue(addr, channel,
  value1, value2, value3, value4...)` — sets several sequential channels
  from one call.
- **`System.DMXCommit()`** (p.86): actually transmits the modified DMX
  frame — values set via `DMXSetValue` are staged, not sent, until this
  is called.
- **Tested hardware** (p.86): Enttec Open DMX USB Interface.

## Voicemeeter Remote API for developers (p.87)

- **VoicemeeterRemote.dll** (p.87): the underlying API installed with
  Voicemeeter; any third-party app, in any language, can use it to
  control every Voicemeeter feature. Core functions named: `Login()`,
  `Logout()`, `GetVoicemeeterType()`, `GetVoicemeeterVersion()`,
  `IsParametersDirty()`, `GetParameterFloat()`, `GetParameterStringA()`,
  `GetParameterStringW()`, `SetParameterFloat()`, etc. Up to 4 client
  applications can remote Voicemeeter/Banana simultaneously through it.
- **Audio Callback API** (p.87, since 1.0.5.0/2.0.3.0): lets a
  third-party app process audio directly *inside* Voicemeeter, at 3
  distinct insertion points (SDK downloadable from the VB-Audio forum):
  1. **AUDIO CALLBACK IN** — at the "Pre Strip Input Insert" point (Pre-
     Fader insert driver), 22 channels in / 22 out.
  2. **AUDIO CALLBACK OUT** — at the "Pre-Master BUS insert driver"
     point, 40 channels in / 40 out (5 buses × 8 channels).
  3. **AUDIO CALLBACK MAIN** — at the main driver combining every I/O
     point; source diagram shows "22x Inputs (channel in)", "40x Inputs
     (channel out)", "40x Outputs (channel out)" — the repeated
     "Inputs"/"channel out" wording in that box looks like a labeling
     inconsistency in the source diagram itself rather than a typo
     introduced here; transcribed as printed, not resolved.

## System Settings / Options dialog, full detail (pp.89-90)

- **Per-device status rows** (p.89): one row per physical input (IN1-5)
  and output (OUT A1-A5), each showing Status (ON/OFF), SR (sample
  rate), buf (buffer size), ch (channel count), r (bit resolution), and
  the bound device's name (or "-none-").
- **OUT A1 Main Device** (p.89): also shows the "PATCH ASIO Inputs to
  Strips" sub-panel when A1 is an ASIO device — per-physical-input ASIO
  channel assignment slots.
- **OUT A2/A4/A5** (p.89): "PATCH BUS TO A1 ASIO Outputs" sub-panels —
  per-bus ASIO output channel assignment slots (matches the ASIO-routing
  mechanism from p.40).
- **Buffering fields, per interface** (p.89): Buffering MME (example
  1024, default 1024), Buffering WDM (example 256, default 512),
  Buffering KS (example 512, default 512), Buffering Clock (example 512,
  default 512), Buffering ASIO (default "Default"), ASIO SR (default
  "Default").
- **Monitoring Synchro Delay** (p.89): one ms-delay field per bus (A1-A5)
  — the per-bus output-delay control referenced elsewhere (spec-relevant:
  "Global per bus output delay... 0 to 500ms").
- **External FX Patch** (p.89): Send1/Return1 and Send2/Return2 ASIO
  channel-assignment slot pairs.
- **OUT Limiter toggle** (p.89-90): **On by default. When on, enables
  brick-wall limiters (based on VB-Audio's own "C-Limiter") on every
  output bus; when off, a simple peak remover is applied instead.** This
  is the exact system-wide toggle governing bus-level limiting referenced
  elsewhere in the manual (p.2's bus signal chain, p.5's bus control
  table) — confirmed here as its own dedicated named control in the
  System Settings dialog, not something to infer indirectly.
- **Internal FX Selection** (p.89-90): a Reverb/C5 toggle — confirms
  again (see pp.37-38) that MultiTap Delay and the C5 multiband
  compressor share one internal-FX slot and are mutually exclusive;
  Reverb is always present separately.
- **VAIO sync dropdown** (p.89-90): example shown "STRICT" — enables
  strict synchronization of every virtual I/O to Voicemeeter's main
  stream (driven by output A1); expected to improve stability,
  especially at low latency.
- **Virtual ASIO Type dropdown** (p.89): example shown "Float32LSB".
- **Preferred Main SampleRate dropdown** (p.89-90): one of 44.1/48/88.2/
  96/176.4/192 kHz — sets output A1's desired rate, though the actual
  result still depends on the device's own current configuration.
- **WDM Input Exclusive Mode dropdown** (p.89): example shown "No".
- **Engine Mode dropdown** (p.89-90): example shown "Normal" — the other
  documented value, "Swift" (an experimental low-latency mode), is noted
  as disabled/deprecated (greyed out in the source) "because generating
  too much support" — alongside a WDM-input-exclusive-mode variant
  disabled for the same reason, tied to a WASAPI exclusive-mode bug
  referenced under Known Issues.
- **PATCH COMPOSITE row** (p.89): the same Composite-Patch UI seen on
  p.32, confirmed to live in this same System Settings dialog (not a
  separate one) — 8 assignable channel slots.
- **Slider Mode toggle** (p.89-90): Absolute (default) or Relative.
  Absolute makes every one of a strip's per-bus sub-mixer gains jump to
  the same value together; Relative preserves their existing relative
  differences when one is adjusted.
- **MONITOR ON SEL toggle + Monitoring BUS dropdown** (p.89-90): lets the
  SEL button also monitor a bus, with a chosen target "Monitoring BUS";
  this is the mechanism Streamer View's own MON button (p.45) relies on
  automatically.
- **PATCH INSERT row** (p.89): "Activate Insert per PRE-Fader Inputs
  (34 channels virtual ASIO Driver)" — a large grid of per-channel
  insert-enable toggles, grouped by input/virtual-input/virtual-bus
  column, labeled "PRE-FX".
- **SR/buf/Ch/r/S field glossary** (p.89): SR = the device's current
  sample rate (independently per device, since the engine is
  multi-point/multi-format); buf = current buffer size for that device;
  Ch = channel count (1-2 on inputs, up to 8 on outputs); r = bit
  resolution (Potato defaults to 24-bit); S = "share mode" indicator
  (WDM only — KS is normally exclusive, MME normally shared, WDM depends
  on the device and engine mode).
- **Output A1 defines the whole engine's rate** (p.90): A1's own device
  configuration (sample rate + buffer size) sets Voicemeeter's main audio
  configuration *and* the virtual ASIO driver's configuration; every
  audio point processes at this rate, with automatic conversion for any
  point actually running at a different one.
- **Internal clock fallback, restated precisely** (p.90): with no device
  selected as output A1, Voicemeeter runs on an internal clock at the
  Preferred Sample Rate and the Buffering Clock value — letting it run
  with no physical output device connected at all.
- **Buffering ranges** (p.90): MME supports 512-2048 samples; WDM/KS can
  go down to 256 samples (near-real-time — explicitly called out as
  usable for singing along in real time, karaoke, or playing a digital
  piano live). Some PC/device combinations are unstable at minimal
  buffering (audible cuts); defaults (MME 1024, WDM 512) are chosen to
  work across effectively all PC configurations.
