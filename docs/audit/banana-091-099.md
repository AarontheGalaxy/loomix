# Voicemeeter Banana manual, pages 91-99

## License activation (continued) (p.91-93)

- **Get Response code from webshop** (p.91): the webshop account's "My License" page lists every owned license (Application, Challenge, Response, Download link, Order reference, Regen left) with Regen/Certificate action buttons per row.
- **Activate license flow** (p.91): enter the registered e-mail and Response code (copy/paste recommended to avoid typos) into the License dialog box, click Activate; a "License Activation" progress dialog ("Sending Authentication Request...") appears; on success the dialog shows "ACTIVATED" in green.
- **Manual activation fallback** (p.92-93): if the automatic Activate call fails (e.g. "Windows Internet Error: 12007, The server cannot be reached"), a manual-entry dialog appears: "To activate your license manually, go in your webshop account 'My License' page... And get your Certificate as a string to paste it below", with "My webshop account" and "Activate" buttons. The webshop's "Certificate" button (next to the relevant license row) generates a certificate string; a "Get License Certificate" confirmation dialog shows the license's Application name, Order reference, Email, Challenge code, and Response code for the user to verify before clicking "Get a certificate now". The resulting certificate text always starts with `>` and ends with `<`; it's pasted into the manual activation box and stored locally so the license is authenticated without needing further internet access.

## Known Issues / Recommendations (p.94-95)

- **"No sound anymore on my computer!"** (p.94): Voicemeeter must be running to pass audio if set as the Windows default device — like switching on a real mixing console. Running Voicemeeter can take exclusive access to its selected output devices (A1/A2/A3), which can prevent other applications from using those same playback devices; as a virtual mixer, every audio source should be connected to Voicemeeter (rather than mixed sources connecting directly to a shared output device) to avoid conflicts.
- **"Voicemeeter does nothing if you don't use it"** (p.94): the application and its virtual drivers are inert if unused and cannot disturb or corrupt the system; a "no sound" complaint is almost always a Windows default-device / dependent-app (Zoom, Discord, Spotify, Games, OBS, etc.) configuration issue, not a Voicemeeter fault.
- **"Output A1, A2, A3... are not exactly synchronized"** (p.94): every Voicemeeter I/O is independent; routing to several different output devices can produce a small audible echo/desync between them (a real, expected technical constraint, not a bug), correctable by adding a per-output delay line in the System Settings dialog's "Monitoring Synchro Delay" fields (OUT A1-A5, 0.00ms default each).
- **"Voicemeeter Audio Stream can be stopped (no more sound, no meter display)"** (p.94): can happen when changing Windows audio configuration, or plugging/unplugging a USB device, or launching another program that grabs the same device. Fix: restart the audio engine, or re-select an audio device on output A1 or input 1 (or any other) to restart the stream automatically; if that doesn't help, the device is likely held by another process.
- **"Voicemeeter Audio Engine works only if the device selected for output A1 is running"** (p.95): selecting no device at all for A1 lets Voicemeeter run on its internal clock, intended for PC configurations with no output device available.
- **"Audio Stream becomes bad (sound is choppy, crackling, discontinued)"** (p.95): if the stream is unstable over time with excessive cuts, the recommendation is to change audio interface or buffer size to find a stable configuration. Specific note: Discord may not work correctly at any sample rate other than 48kHz, so Voicemeeter's virtual output (the recording device Discord reads from) may need to be explicitly set to 48kHz via Windows Sound's Advanced/Default Format tab (screenshot shows the format dropdown with entries like "2 channel, 24 bit, 48000 Hz (Studio Quality)").
- **"Windows Update can disturb audio"** (p.95): WIN10/WIN11 updates can change default settings/privacy rules affecting microphone access, or (WIN11) a power-throttling feature can destabilize the stream when the application window is minimized.

## VB-Audio Device Checker (p.96-97)

- **VBDeviceCheck.exe** (p.96): still listed in the Voicemeeter menu but no longer auto-run at startup (unlike earlier versions). Originally built to detect a Windows-update-triggered driver re-installation problem (icon/pin-name/driver-info reset); largely superseded now that the current VAIO/VB-CABLE drivers are Win10+-oriented and let users change pin name/icon themselves.
- **Device Checker output** (p.96, screenshot): a log-style report per virtual device (e.g. "CHECKING VB-Audio Virtual Cable (version...): version number warning (driver not updated)", "CHECKING VB-Audio Cable A: Not Installed", etc.), ending with an Initialization value, Test date, OS version/build, and a CONCLUSION line (e.g. "OK (nothing bad detected)"). Manual notes the old individual VoiceMeeter VAIO/AUX/VAIO3 drivers are "no more installed" on Windows 10+ (superseded by a single combined driver with 8 I/O) — version-mismatch warnings for those can be ignored.
- **Audio Device List view** (p.96-97): a Devices menu option ("Show Device List" / "Refresh Device List") lists every VB-Audio virtual playback/recording device with its current audio format and exclusive-mode properties in parentheses (matching what Windows Sound shows for the pin) — notes some properties aren't always reported correctly/consistently.

## Where settings files are stored (p.97)

- **Settings file location** (p.97): all Voicemeeter and MacroButtons current settings are stored as XML files under `My Documents\Voicemeeter` (e.g. `Scene_Banana.xml`, `Scene_Potato.xml`, `Scene_Standard.xml`, `MacroButtonConfig.xml`, various `VoicemeeterXXX_LastSettings.xml`/`_TodaySettings.xml`/`_YesterdaySettings.xml`).
- **"Today" / "Yesterday" settings snapshots** (p.97): per edition, the config manager automatically maintains two rolling settings snapshots — "Today" (configuration state at the start of the current day) and "Yesterday" (the configuration file that was in use the day before) — a simple daily undo/rollback mechanism, distinct from the user-managed Preset Scene list.

## Command Line Installation (p.98)

- **Setup command-line switches** (p.98): `-h` (hide GUI), `-i` (install), `-u` (uninstall). Recommends first uninstalling any previous version, rebooting, then installing the new version and rebooting again — reboot is required after both install and uninstall.

## Voicemeeter Command Line (p.98)

- **`Voicemeeter.exe -R` (or `-r`)** (p.98): restarts the audio engine via a shortcut — useful e.g. to reactivate a USB headset that was unplugged and replugged, without opening the app UI.
- **`-l"filename.xml"` / `-L"filename.xml"`** (p.98): runs Voicemeeter with a specific configuration file loaded at startup; case variants for relative-to-exe, relative-to-subfolder, or absolute path (`-l"subfolder\filename.xml"`, `-l"c:\folder\filename.xml"`). Only takes effect if Voicemeeter was not already running (a call while it's running does nothing) — lets different desktop shortcuts launch Voicemeeter pre-configured for different jobs.

## Registry Parameters (p.99, advanced/expert only)

All under `HKEY_CURRENT_USER\VB-Audio\VoiceMeeter`; manual warns not to modify without vendor support guidance.

- **DelayedStartS** (p.99): countdown in seconds (default 5) before starting the audio engine on Voicemeeter startup, shown as a growing bar/countdown on the device-selection area, to give audio services/drivers time to be ready first.
- **preferredResolution** (p.99): preferred bit resolution (Banana & Potato default 24 bits; Standard is always 16 bits with Windows Audio Interface). Final resolution is negotiated with the actual audio interface, which can force a different value.
- **MaxMonDelayMS** (p.99): default 500ms, the ceiling for the "Monitoring Synchro Delay" options in System Settings; redefinable via registry from 500ms to a max of 5000ms (5 seconds).
- **PreRecordingTimeMax** (p.99): 10 to 60 seconds (default 20) — the pre-recording rolling-buffer memory allocation size made at Voicemeeter startup (e.g. ~90MB for 60 seconds at 48kHz).
- **TimerResolution** (p.99): default 1 — forces the system timer resolution to 1ms; set to 0 to use the (coarser) 0.5ms-granularity default OS timer resolution instead. (Note: manual's own wording is inverted/unclear about which value means which granularity — recorded verbatim as written, flagged here rather than silently corrected.)
- **AutoUpMixMode** (p.99): if set to 1, an Up Mix bus mode auto-detects whether the incoming signal is genuinely stereo or already multichannel — considered multichannel if signal above -80 dBFS is detected on channel 3, 4, or 5 — and in that case the Up Mix transform is *not* applied. This is the exact vendor-documented feature (with the precise -80dBFS/channel-3-4-5 threshold) that an earlier, since-reverted pass through this codebase's audit had already flagged as missing from `docs/SPEC.md`'s Up Mix section (1.6) — now confirmed directly from the manual with a page citation rather than secondhand.
- **WARNING (manual's own text, p.99)**: "Other registry values must not be modified directly."
- **EngineMode (AUDIO EXPERT / DEVELOPERS only)** (p.99): a bit-field controlling WASAPI audio engine behavior; must be ZERO by default, and the manual states these modes "are not tested anymore in our dev cycle" (i.e. vendor-deprecated/unsupported). Bit values: `0x00000001` = MODE_SWIFT, `0x00000100` = INPUT EXCLUSIVE MODE, `0x00000200` = OUTPUT EXCLUSIVE MODE ("set anyway in Voicemeeter" — meaning output exclusive mode is applied regardless of this flag). This is the same SWIFT/exclusive-mode combination the manual's own System Settings section (pages 78-79) already described as disabled/experimental/potentially unstable.
