# Voicemeeter Potato manual, pages 61-75

## VBAN-Screen (p.61)

- **VBAN-Screen application** (p.61): a PC app (Mac/other planned) that
  can monitor up to 4 video streams simultaneously via VBAN-Frame,
  alongside VBAN-Audio streams. UI shows 4 parallel "VBAN-Screen N"
  panel groups (1-4), each with its own Text Command IN row (stream
  name/IP/port/format/net-quality/errors), Audio Stream IN row, Video
  Stream IN row, and a Mouse command OUT row.
- **Magic-board drawing** (p.61): VBAN-Screen can also display freehand
  drawing data delivered over a VBAN-Text incoming stream.
- **Outgoing mouse control** (p.61): VBAN-Screen offers its own outgoing
  VBAN-TEXT stream to send Mouse Move / Left-Click / Right-Click (Right
  via holding Ctrl) commands to whatever it's viewing — the other
  direction of the p.58 remote-mouse feature (here, VBAN-Screen is the
  controller).

## Macro Buttons overview (p.63)

- **Macro Buttons application** (p.63): installed with Voicemeeter;
  displays 4 to 80 programmable buttons, each either Push or 2-Position
  mode, with a title/subtitle, assignable to a keyboard shortcut, mouse,
  gamepad, MIDI message, or audio-level trigger.
- **Remote-API demonstration** (p.63): an independent application built
  on the Voicemeeter Remote API — proof that any custom client app can
  automate Voicemeeter, implement VCA/auto-ducking, or process audio
  directly via its various interfaces.
- **Documented use cases** (p.63): mute a strip or bus; change gain on
  one or several strips/buses; change or toggle bus assignment on one or
  several strips; combine multiple requests into one complex action
  (example: a push-to-talk or auto-ducking button that sets Music gain
  to -10dB *and* mutes another talker simultaneously); change voice
  color/audibility for a special announcement; restart the audio engine;
  save or load a complete configuration file.
- **Banana-only extras** (p.63): trigger voice FX via the
  Modulation/Color pad; launch playback via the integrated recorder;
  apply bus-parametric-EQ corrections; remote every VBAN function.
- **System-level functions** (p.63): send a keyboard event to the system
  queue (to remote other applications); execute any program (optionally
  with a command line); send a MIDI message to up to 2 devices; send
  VBAN-MIDI or VBAN-TEXT requests.

## Configuring a Macro Button (p.64)

- **3 scripts per button** (p.64): an initial-state script (sent on
  Voicemeeter startup), a script sent when the button is pushed, and one
  sent when it's released.
- **Button Configuration dialog fields** (p.64): Button Name; Button
  Color (dropdown); Button Type (Push Button / 2 Positions); Button Sub
  Name; GPIO (dropdown, default "no"); Keyboard Shortcut (dropdown of
  key/mouse combinations) + Exclusive Key checkbox; Image filename
  (native resolution 130×108, separate "Select File Off"/"On" pickers);
  Request For Initial State (free text); Request for Button ON/Trigger IN
  (an event-source dropdown, default "No event", plus a free-text script
  box); Request for Button OFF/Trigger OUT (same shape); M.I.D.I.
  Implementation (a Learn checkbox that captures from the MIDI-mapping
  device, a Reset button, and a readout of the captured MIDI code);
  XINPUT (Enable checkbox, a Ctrl/controller-index dropdown, a GamePad
  Button dropdown); a TRIGGER section (below); HID Device Button (a
  Config button to bind directly to any HID device).
- **TRIGGER sub-section** (p.64): Enable checkbox; Strip selector; In
  threshold and Out threshold fields (with a visual slider showing a
  green marker for In, a red marker for Out); Hold time field; Input Mode
  selector (e.g. Pre-Fader). The button is pushed once the strip's level
  crosses above the In threshold, and released once it falls below the
  Out threshold; Hold defines the minimum time the button stays engaged
  regardless of level.
- **M.I.D.I. Implementation semantics** (p.64): MIDI codes come from
  whichever device is selected in the MIDI Mapping dialog, and can also
  arrive via an incoming VBAN-MIDI stream.
- **XINPUT semantics** (p.64): up to 4 gamepads can be bound to control
  buttons.

## Button color / image / Voicemeeter events (p.65)

- **Button Color palette** (p.65): 8 selectable background colors shown
  swatched 1-8 (an orange/gold/green/teal/blue/purple/magenta/red
  sequence); the p.64 text separately states "9 different button
  backgrounds" for Button Type overall — likely counting the default
  (unset) color as a 9th option alongside these 8, not a contradiction
  the manual itself resolves explicitly.
- **Button Image** (p.65): a button can show one image for its OFF state
  and a different one for ON, set via the two "Select File Off"/"On"
  pickers; native resolution 130×108 px; BMP, PNG, JPG, or TIF accepted;
  larger images are reframed/scaled, smaller ones centered. Transparency
  (with shadow) is only handled correctly for a PNG *smaller* than the
  native resolution. Once an image is assigned, the keyboard shortcut
  label is no longer shown on the button face.
- **Voicemeeter Event trigger source** (p.65): the Trigger IN/OUT
  dropdown can bind a button's script to a Voicemeeter-internal event
  instead of a manual push — specifically the tape recorder's own
  transport events: **Tape Play, Tape Stop, Tape Rec, Tape EndOfFile**
  (alongside the default "No event").

## Remote request syntax / control-name map (pp.65-66)

- **Request syntax** (p.65-66): a structured control/parameter name
  followed by `=` and a value or string; some instructions are
  case-sensitive, so the manual recommends capitalizing the first letter
  of every word.
- **Full strip/bus index diagram** (p.66): a labeled screenshot
  confirming the internal naming scheme end to end — `Strip[0]` through
  `Strip[7]` map left-to-right onto the 5 hardware + 3 virtual strips
  (`Strip[0].Color_x/y`, `Strip[1].Reverb`/`.Delay`, `Strip[1].A1`/`.B1`/
  `.Mono`, `Strip[2].Gain`/`.Fx1`/`.Fx2`/`.PostFx2`/`.PostReverb`,
  `Strip[3].Comp`/`.Gate`/`.PostDelay`, `Strip[4].Solo`/`.Mute`,
  `Strip[5].EQGain3`, `Strip[6].EQGain1`/`.Pan_x`/`.Pan_y`,
  `Strip[7].MC`), and `Bus[0]` through `Bus[7]` onto the 8 buses
  (`Bus[0].ReturnReverb`/`.ReturnFx1`/`.EQ.On`, `Bus[1].ReturnDelay`/
  `.Sel`/`.Mono`/`.Mute`, `Bus[2].Gain`, `Bus[4].ReturnFx2`).
- **Numeric request examples** (p.66, verbatim): `Strip(0).mute=1;` //
  mute the first strip; `Strip(0).mute=0;` // unmute; `Strip(0).mute
  +=1;` // toggle current mute state; `Bus(0).mono=1;` // set first bus
  to mono; `Bus(0).gain=-10.0;` // set bus gain to -10dB;
  `Strip(0).gain=+6.0;` // set strip gain to +6dB; `Bus(0).gain +=3.0;`
  // relative +3dB; `Strip(0).gain -=3;` // relative -3dB;
  `Command.Restart = 1;` // restart the audio engine.
- **String request example** (p.66, verbatim): `Command.Load=
  "C:\My Documents\VMConfig1.xml";` // load a config file.

## Remote API: bus devices, internal FX, fades (p.70)

- **Bus audio-device selection** (p.70, physical bus only): `Bus[i]
  .device.wdm`/`.ks`/`.mme`/`.asio` — device name, write only, API v1.
- **Internal FX on/off + memory** (p.70): `Fx.Reverb.On` (0/1, v3),
  `Fx.Reverb.AB` (0=A/1=B, v3), `Fx.Delay.On` (0/1, v3), `Fx.Delay.AB`
  (0=A/1=B, v3) — note `Fx.Delay` addresses whichever of MultiTap Delay
  or C5 is currently the active second-FX-slot effect (p.37's mutual
  exclusivity), the API name doesn't change based on which is selected.
- **Timed fade** (p.70): `Strip().FadeTo`/`Bus().FadeTo` set the gain
  slider with a progressive fade to a target dB value over a given time
  in ms (0 to 120000 max), as a 2-value string parameter. Examples:
  `Strip(0).FadeTo= (-10.0, 500);`, `Strip(0).FadeTo= (-20.0, 2000);`,
  `Bus(0).FadeTo= (0.0, 1500);`. `FadeBy` (relative dB change instead of
  absolute target) works the same way.
- **Patch Options table** (p.70, System Settings scriptable
  equivalents): `patch.asio[i]` (0 to ASIO input, "ASIO Patch", v1);
  `patch.OutA2[i]`/`.OutA3[i]` (0 to ASIO output channel, v2);
  `patch.OutA4[i]`/`.OutA5[i]` (v3); `Patch.composite[j]` (0 to 22, 1 =
  first channel, 0 = default bus content, v2 — the Composite Patch);
  `Patch.insert[k]` (0/1, "Virtual ASIO insert", v2); `Patch
  .PostFaderComposite` (0=PRE/1=POST, v2); `Patch.PostFxInsert`
  (0=PRE/1=POST, "Virtual INSERT Point", v2). (`i` = input channel
  zero-based index, physical strips only, 2 channels/strip; `j` =
  composite channel zero-based 0-7; `k` = input channel zero-based 0-21.)

- **Command-ordering semantics** (p.72): command requests are processed
  *before* any other request type in the same packet. A Shutdown
  request closes the program without processing the rest of that
  packet's requests; a Load request resets and discards every other
  request present in the same packet.
- **Eject semantics** (p.72): releases the recorder's held audio file so
  other applications can access it.
- **Command.Button restriction** (p.72): must only be used inside a
  VBAN-TEXT request, never a local script (called out explicitly as a
  warning).

## Remote API: button interaction / sequencing commands (p.73)

- **Button(N).State** (p.73): `=1` pushes button N, `=0` releases it
  (simulating a manual press/release from script).
- **Button(N).StateOnly** (p.73): sets the pushed/released visual state
  without running the button's own push/release scripts.
- **Button.State (no index)** (p.73): only valid inside a button's own
  INIT script — changes the state of the current (self) button.
- **Button(N).Trigger** (p.73): `=1`/`=0` enables/disables the audio
  Trigger on button N.
- **Wait command** (p.73, added Sept 2019): introduces a timed pause (ms)
  between requests within one script, to sequence a series of changes —
  example: set a gain, `Wait(2000)`, change it again, `Wait(1000)`, fade,
  `Wait(1000)`, fade again.
- **Load Button map** (p.73, added March 2020): `Load("filename");`
  loads a different Macro Buttons config file (previously saved via the
  app's own system-menu Save), from inside a script.
- **Show command** (p.73, added Oct 2021): `Show(0);`/`Show(1);` hides
  or shows the Macro Buttons GUI window; the manual explicitly warns to
  remember to call `Show(1)` somewhere or the app becomes unreachable.

- **MIDI-source route bit combination** (p.74): `route` for a MIDI
  outgoing stream is a bitmask: MIDI Input=0x01, MIDI Aux input=0x02,
  VBAN IN=0x04, MIDI OUT=0x08. Example: "ALL MIDI IN" =
  0x01+0x02+0x04 = 7.
- **Restart-triggering parameters** (p.74): changing `vban.Enable`,
  `vban.instream[i].port`, `vban.instream[i].quality`, or
  `vban.outstream[i].quality` triggers a full audio-engine restart.
- **VBAN sample-rate list** (p.74): 11025, 16000, 22050, 24000, 32000,
  44100, 48000, 64000, 88200, 96000 Hz.
- **VBAN Quality levels** (p.75): 0 Optimal, 1 Fast, 2 Medium, 3 Slow, 4
  Very slow — trades internal buffering (and thus latency) for
  resilience against network jitter; tuning this matters mainly on the
  receiver side, since a transmitter is expected to always run Optimal.
- **VBAN Bit Resolution values** (p.75): 1 = 16-bit PCM, 2 = 24-bit PCM.

## AUTO Ducking / Trigger, worked example (p.75)

- **Auto Ducking via the button Trigger mechanism** (p.75): reuses the
  same per-button audio-level Trigger described on p.64 to implement
  ducking or drive any other parameter/function (example given: a REC
  button) from an input strip's level, rather than a manual push.
- **Worked example** (p.75): a button named "Auto ducking" (sub-name
  "Me/music"), Trigger enabled on strip "in #1", In threshold -15.7 dB,
  Out threshold -35.4 dB, Hold 100 ms, Input Mode Pre-Fader. Trigger-IN
  script: `Strip[3].FadeTo=(-15.0,100); Strip[3].EQgain2=-12;`.
  Trigger-OUT script: `Strip[3].fadeto=(0,200); Strip[3].EQgain2=0;` —
  ducks strip 3's gain and its EQ band 2 while strip 1's level is above
  threshold, restoring both once it drops back out.
