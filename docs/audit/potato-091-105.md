# Voicemeeter Potato manual, pages 91-105

## ASIO driver support (p.91)

- **ASIO as output A1** (p.91): lets Voicemeeter run in "audio pro"
  conditions, the same way a DAW would use an ASIO device.
- **ASIO Control Panel access** (p.91): click the A1 device's own name in
  System Settings to open its ASIO Control Panel directly.
- **ASIO input routing to hardware strips** (p.91): if the A1 device is
  ASIO, its first input channels can be routed onto Voicemeeter's
  physical strips via the "PATCH ASIO Inputs to Strips" panel — pick
  which ASIO channel feeds IN#1 Left/Right, IN#2 Left/Right, etc.
  (applies only for a strip with no *other* input device already
  selected).
- **ASIO output routing to unused buses** (p.91): selecting ASIO as A1
  sends audio to its first 8 output channels automatically (bus A1);
  other buses can be routed to other ASIO output channels via the
  "PATCH BUS TO A1 ASIO Outputs" panels (matches p.40's mechanism, now
  shown with its exact UI captions).
- **ASIO Buffering, two independent parameters** (p.91): "Buffering
  ASIO" can either use the ASIO driver's own default buffer size, or be
  forced to a specific size (the driver may refuse or misbehave for some
  forced values); "ASIO SR" chooses between the driver's own default
  sample rate or Voicemeeter's Preferred Sample Rate.
- **Getting optimal latency** (p.91): the A1 device choice is described
  as *the* critical latency decision, since it sets the master sample
  rate and main buffer size; ASIO preferred, then WDM, then KS.

## Latency tuning (p.92)

- **Buffer-size reduction** (p.92): manually lowering buffer size (e.g.
  to 256) improves latency, especially with WDM/KS devices.
- **SWIFT mode** (p.92): a further latency-reducing mode for WDM
  devices, described here as selectable but "not recommended because
  might be unstable" — note this appears to contradict p.90's own
  wording that Swift mode "has been disabled because generating too much
  support" (a possible internal inconsistency between these two sections
  of the same manual, both read directly, not reconciled here).
- **Disabled WDM-exclusive-input option** (p.92, grayed text in source):
  activating WDM Input Exclusive mode (together with Swift) would force
  the smallest possible buffer on WDM input devices, but exclusive mode
  was found unstable (audio crashes up to full system freeze/crash,
  depending on driver/OS) — see Known Issues.
- **VAIO internal-latency tuning** (p.92): virtual I/O latency can also
  be reduced via the VAIO driver's own "VBCABLE Control Panel" program
  (apparently another name for the same VAIO Control Panel seen on
  pp.48-50) — but reducing it too far can cause a discontinuous or
  non-working stream in some cases.
- **Virtual ASIO's own added latency** (p.92): the virtual ASIO driver
  adds exactly one buffer's worth of latency to the global figure, sized
  by output A1's own buffering setting.
- **Sub-256-sample instability** (p.92): going below 256 samples (at
  44.1/48kHz) can cause audio stability problems; revert to the default
  buffer size if this happens.
- **Patch Composite, restated with clearer captions** (p.92): the same
  8-channel Composite Patch UI as p.32 — click a channel slot to assign
  a different Voicemeeter input to it; click the "Select PRE-Fader
  Inputs..." label itself to toggle the whole patch to POST-FADER mode.
  References "USE CASE #3" in the (Standard) Voicemeeter manual for a
  worked example — confirms Standard's manual carries numbered "use
  case" walkthroughs that Potato's manual doesn't repeat, only
  cross-references.

## Patch Insert (p.93)

- **Patch Insert** (p.93): activates a pre-fader insert per input
  channel, but only takes effect once an application is connected to the
  "Voicemeeter Potato Insert ASIO Virtual Device Driver" — a *single*-
  client ASIO driver exposing up to 34 channels covering Potato's 8
  strips, meant for hosting a VST plug-in chain (e.g. a VST host app)
  in-line with any Voicemeeter input.
- **Insert-point toggle** (p.93): PRE-FX or POST-FX, chosen once for the
  whole insert driver (not per channel).
- **Live insert indicator** (p.93): once a DAW/ASIO app is actually
  connected to the Virtual Insert, a small "i" icon appears at the
  top-left of every strip that has an active insert return, so you can
  see (and toggle) which strips are actually being processed externally.
- **Full internal-routing diagram** (p.93): traces Windows input devices
  → ASIO Patch → A1's ASIO input channels → (optionally) VBAN → the
  Virtual ASIO Driver → the pre-fader Composite-Patch receive point →
  the Virtual Insert point → the strips themselves — showing Composite
  and Insert share the same conceptual pre-fader tap point in the signal
  path, just for different purposes.

## MIDI Mapping (pp.94-96)

- **MIDI Mapping dialog overview** (p.94): binds a MIDI remote surface
  to gain/mute/solo (with feedback) on every strip and bus, plus support
  for a secondary "MIDI Extra Input Device". Top fields: M.I.D.I. Input
  Device selector, M.I.D.I. Map Name field, **Reset Map** / **Load
  M.I.D.I. Map** / **Save M.I.D.I. Map** buttons, M.I.D.I. Output Device
  (feedback) selector, M.I.D.I. Extra Input Device selector, VBAN
  M.I.D.I. input selector, **Refresh Controller** button.
- **Mapping grid, per row** (p.94): control name, learned MIDI message
  readout, **Learn** button (or Tab/arrow keys to step to the next/
  previous row while learning), and an **F/FF** feedback-mode toggle.
  Paginated (Page 1/4 shown). Confirmed mappable controls on this first
  page: Gain Fader Strip #1-5, Gain of Virtual Strip #6-8, L/R PAN Strip
  #1-5, L/R PAN Virtual Strip #6-8, **PTT** Mute Strip #1-3 ("Push To
  Talk" — a distinct un-mute-on-press/mute-on-release variant of Mute,
  not a toggle), Mute Strip #4 / Mute Virtual Strip #6-8, Solo Strip
  #1-5, Solo Virtual Strip #6-8, **M.C. Virtual Strip #6/#8**, **K Button
  Virtual Strip #7** (the Karaoke button, MIDI-mappable specifically on
  the AUX virtual strip), Compression Strip #1-3 (continues past this
  page).
- **Learn / reset gestures** (p.94): click Learn then move the physical
  control; click the (black) MIDI-code readout area to reset that one
  mapping back to unlearned.
- **Refresh Controller** (p.95): re-sends every MIDI feedback message
  reflecting Voicemeeter's *current* state (a full resync) — also
  available as its own MIDI-mappable function (assignable to a button on
  a later mapping page, per the manual's own forward reference).
- **MIDI Feedback** (p.95, added March 2021): Voicemeeter can drive a
  MIDI Output Device to move a motorized fader or light an LED, matching
  its own current state, via the F/FF modes.
- **F = simple feedback** (p.95): the controller is updated whenever the
  mapped parameter changes for *any* reason (mouse, VBAN, anything other
  than that MIDI controller itself); sufficient for ordinary knobs/
  faders.
- **FF = double feedback** (p.95): needed for MIDI controllers with LED
  buttons (must recolor to match Voicemeeter's button state) and for
  some motorized faders that need explicit position acknowledgment
  (otherwise some surfaces auto-return the fader to its initial
  position).
- **MIDI Forward** (p.95): mapping can ingest MIDI from 2 physical
  controllers plus an incoming VBAN-MIDI stream simultaneously; every
  received message is also forwarded automatically to the Macro Buttons
  app. Since March 2021, incoming MIDI can *also* be forwarded back out
  over an outgoing VBAN-MIDI stream, letting MIDI (including feedback)
  reach a controller on a different computer over the network.
- **MIDI Advanced Feedback** (p.96, added Nov 2022): lets a 2-position
  control's feedback values be redefined (default 127=ON, 0=OFF) for
  controllers that display different colors per numeric value.
  Right-click the "F" button to open the **MIDI Feedback Options**
  dialog: Feedback Value ON, Feedback Value OFF, Feedback Message ON
  (HEXA, free text, supports SYS-EX), Feedback Message OFF (HEXA) — lets
  a fully custom (including sys-ex) message target other devices, like a
  MIDI LCD or a machine-control surface.
- **Duplicate-mapping detection** (p.96): a MIDI message shown in
  **yellow** in the grid means it's already bound to one or more other
  mapped parameters; right-click it to see the first parameter using
  that same message.

## Specifications (pp.97-98)

Exact specification table:

- **Device Type**: PC-Core Virtual Audio Mixing Console.
- **Compatibility**: XP(SP2), Vista, Win7, Win8, Win10/11 (32/64-bit).
- **PC Configuration**: min. Celeron/Duo Core 1.8GHz, 512MB RAM, <100MB
  disk.
- **I/O count**: 8 inputs (5 physical/3 virtual), 8 outputs (5
  physical/3 virtual).
- **Bus/Layer**: 8× bus (A1-A5, B1-B3) / multi-layer.
- **Audio Engine Capabilities**: 32, 44.1, 48, 88.2, 96, 176.4, or
  192 kHz DSP processing (set by output A1's configuration).
- **Output A1 (Main)**: WDM, KS, MME, ASIO (32-192 kHz), 1-8 channels.
- **Output A2-A5**: WDM, KS, MME (8-192 kHz), 1-8 channels.
- **5× Physical Inputs**: WDM, KS, MME (8-192 kHz), mono or stereo.
- **3× Virtual I/O**: WDM, KS, MME, DirectX, WaveRT (8-192 kHz), 1-8
  channels; 8 channels on virtual input, 2 on virtual outputs (possibly
  8 with the KS interface).
- **3× Virtual ASIO I/O**: ASIO (32-192 kHz), 8 channels in/out, up to 4
  client applications; configuration follows output A1's own SR/
  buffering.
- **1× Virtual Insert ASIO I/O**: ASIO (32-192 kHz), 8 channels in/out,
  a *single* client application; configuration follows output A1.
- **M.I.D.I. Implementation (remoting)**: listed here as "Gain faders,
  Mute, Solo, M.C., Audibility, 3 Bands EQ, Transport (configured by
  Learn process)" — narrower than what the actual mapping grid on p.94
  showed (which also included L/R Pan, the Karaoke K-button, and
  Compression); flagged as a discrepancy between this summary table and
  the detailed dialog documented two pages earlier, not resolved by the
  manual itself.
- **Strip Processing** (bulleted list, exact): 6-band full parametric
  EQ; "Color Panel" control (equalization); "Modulation" control
  (chorus/phaser/modulation); 3D panoramic control (binaural source
  positioning); Audibility-knob compressor + detailed parameters;
  Audibility-knob gate + detailed parameters; denoiser knob; 3-band
  graphic equalizer (virtual input); limiter (threshold on the meter
  bar, -40dB to +12dB); send/return/post for internal reverb/delay FX;
  send/return/post for external FX (ASIO AUX/RETURN); slider gain/mono/
  mute/solo.
- **BUS Processing** (bulleted list, exact): integrated 0dBFS limiter
  and peak remover; mix-down to convert 5.1/7.1 to stereo; stereo repeat
  (signal copied onto channels 3/4, 5/6, 7/8); master full parametric
  EQ (6 cells/8 channels); mute/mono/cross(reverse).
- **Others**: physical-output synchronization delay, in the System
  Settings dialog box.

## Potato I/O diagram (p.98)

- **Full signal-path diagram** (p.98): a mixing-console-style I/O
  diagram — physical devices → Voicemeeter Input/Aux Input/VAIO3 Input
  → ASIO/insert points → strips → buses → outputs — presented "like a
  regular mixing console, even if connections are not made by real
  wire."
- **Dual virtual-I/O interface confirmation** (p.98): every virtual I/O
  exposes both a Windows interface (MME/KS/WASAPI/DirectX) *and* an ASIO
  interface (Steinberg spec), so ordinary Windows apps and pro-audio DAWs
  can both connect to the same virtual point.
- **External FX I/O restriction, restated** (p.98): assignable only when
  an ASIO device is selected as output A1 with enough spare channels
  (repeats pp.39-40's point).

## License / activation mechanics (pp.99-105)

Business/DRM UI, no audio-mixer relevance — noted for completeness per
"every menu item" but not classify-able against the mixer feature
inventory. Voicemeeter Potato is "donationware requiring an activation
code" after a 30-day grace period (p.3's licensing note, detailed here):

- **About Box / License dialog** (p.99): reachable from the main menu;
  shows a "Buy Online" button (redirects to the VB-Audio webshop with a
  per-PC "Challenge code" pre-filled), a Registered e-mail field, and a
  Challenge code / Response code pair with an "ACTIVATED" status
  indicator once a valid response code is entered.
- **Hide e-mail address** (p.100): right-click the "ACTIVATED" area to
  toggle hiding the registered e-mail (persisted in the registry).
- **Use Computer Footprint** (p.100): right-click the Challenge code to
  Export/Import a "computer footprint" file (e.g. onto a USB key), to
  re-activate the same license after a Windows reinstall without
  re-purchasing.
- **Activation Log** (p.100): `Voicemeeter_ActivationLog.dat` in
  `My Documents\Voicemeeter`, carried manually between Windows
  installations to preserve activation history for support diagnosis.
- **x64 activation key note** (p.101): the same Challenge/Response pair
  works for both the 32-bit and 64-bit builds.
- **VAIO Extension Activation Code** (p.101): a *separate* purchasable
  license (its own Challenge/Response pair, own dialog: "Extra VAIO
  Feature License") specifically enabling VAIO routing for stereo input
  strips 1-5 and physical buses A1-A5; Potato's VAIO Extension license
  is distinct from the one used by Standard/Banana.
- **License activation process** (pp.102-105): Buy Online (opens the
  webshop with the challenge code pre-filled, contribution-tier
  selection, "Add to cart"); Get your Response code (from the webshop
  account's "My License" page, which also offers a "Regen" option per
  license); Activate your license (paste e-mail + response code, click
  Activate, which contacts VB-Audio's server for an authentication
  certificate stored locally); Activate manually (if offline or the
  server is unreachable — paste a certificate string obtained separately
  via "Get License Certificate" on the webshop, starting with `>` and
  ending with `<`).
