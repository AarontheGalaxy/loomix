# Voicemeeter Banana manual, pages 46-60

## VBAN2MIDI usage walkthrough (p.46)

- **Two-PC MIDI-over-network scenario** (p.46): Step 1 — connect a MIDI controller on PC1 to VBAN2MIDI to manage outgoing/incoming VBAN MIDI stream: outgoing side is MIDI Controller -> MIDI Input Device -> VBAN2MIDI -> target IP address; incoming side (MIDI feedback) is any IP address -> VBAN2MIDI -> MIDI output device -> MIDI Controller In.
- **MIDI mapping + VBAN-MIDI interaction** (p.46): Step 2 — MIDI mapping always accounts for the incoming VBAN-MIDI stream activated in the VBAN dialog box (stream name must match on transmitter and receptor side, e.g. "MIDI1"). Incoming MIDI messages are visible in the VBAN dialog box and can be "learned" onto a control in MIDI Mapping. Manual notes a labeling inconsistency: "VBAN MIDI Input" in the MIDI mapping dialog box is actually related to the VBAN MIDI *outgoing* stream and should be labeled "VBAN MIDI Output" instead (acknowledged documentation/UI wording bug).

## Screen Sharing / mirroring with VBAN-Frame (p.47-50)

- **VBAN-Frame protocol** (p.47): sends a video stream over the local network from a screen capture; Voicemeeter can capture one of 4 connected displays, or its own main window view, to mirror onto another device.
- **VBAN FRAME outgoing stream row** (p.47): an additional outgoing-stream type. Source options: "App View" (capture Voicemeeter's own main window) or "Display 1-4" (capture an entire connected display, up to 4K resolution). Sends PNG or JPG frames at up to 30 times per second to a destination address.
- **Frame rate options** (p.47, screenshot menu): 1, 2, 3, 5, 10, 20 (checked/example), 24, 25, 30 FPS.
- **Image format options** (p.47, screenshot menu): JPG, PNG (checked/example), plus a "Capture Mouse Cursor" toggle (checked).
- **JPG quality percent** (p.47): a percent parameter controls JPG compression quality (0-100%, e.g. "50%" in the screenshot).
- **Net quality / bitrate cap** (p.47): a "net quality" bitrate limit (default 12 Mbps) is a soft target to prioritize the audio stream's bandwidth, not a hard cap (manual notes it "does not prevent to have 30mbps or more").
- **Mouse Management for remote control** (p.47): when receiving VBAN-FRAME via the VBAN-Screen companion app, Voicemeeter can also receive mouse events from VBAN-Screen over a VBAN-TEXT stream, letting it be controlled remotely. Enabled by right-clicking the samplerate/format field on the relevant incoming VBAN-TEXT stream to activate "Mouse Management"; an "M" indicator confirms Voicemeeter is processing mouse events (`System.Mouse=(MOUSEMOVE, x, y)` style commands shown in the stream's "last received" field). A "Manage Mouse command" checkbox governs this.
- **Screen Mirroring ("App View" source)** (p.48): shares only Voicemeeter's own main interface view via VBAN-Frame. Capture works even while the Voicemeeter window is in the background/hidden behind other windows, as long as it's open. Destination IP `127.0.0.1` sends the stream to the same PC; if VBAN-Screen runs on the same PC, a different UDP port should be used than the main VBAN port. PNG recommended to preserve full image quality.
- **Screen Sharing ("Display N" source)** (p.49): shares an entire physical display (e.g. "Display 1", "Capture Your entire first display") rather than just the app window. JPG recommended to reduce network bandwidth, with an adjustable JPG Quality percent (1-100%).
- **VBAN-Screen companion app** (p.48-50): installed with the VB-Audio Matrix package, or downloadable separately from the vendor's VBAN page. Resizable window; can be used to view a smaller Voicemeeter view on the same or a different networked computer.
- **VBAN-Screen: monitor up to 4 video streams** (p.50): the app can display 4 independent "VBAN-Screen 1-4" panels simultaneously, each with its own Text Command IN, Audio Stream IN, Video Stream IN, and Mouse command OUT row (Stream Name / IP Address / Port / Format / Net Quality / Errors columns per row).
- **VBAN-Screen drawing/magic-board feature** (p.50): can display freehand drawing sent over an incoming VBAN-Text stream, usable as a shared "magic board".
- **VBAN-Screen outgoing mouse control** (p.50): offers its own outgoing VBAN-TEXT stream to send Mouse Move, Left Click, and Right Click (using the Ctrl key for right-click) back to whatever is sending the VBAN-Frame video.

## MACRO-Buttons application (p.51-54)

- **MACRO BUTTONS app** (p.52): installed with Voicemeeter; displays 4 to 80 programmable buttons, each Push or 2-Positions mode, with a title/subtitle, and assignable to a keyboard shortcut, mouse action, gamepad input, MIDI message, or Audio (level) Trigger.
- **Built on the Remote API** (p.52): MACRO BUTTONS is itself built using the Voicemeeter Remote API, demonstrating how a client application can control Voicemeeter by program (including building custom automation, VCA, Auto Ducking, or direct audio processing via the available interfaces/APIs).
- **Example use cases listed** (p.52): mute a strip or bus; change gain on one or several strips/busses; change/toggle bus assignment on one or more strips; combine several requests into one complex action (e.g. a Push-To-Talk or Auto Ducking function that sets Music gain to -10dB and mutes another talker simultaneously); change voice color/audibility for special announcements; restart the audio engine; save/load a complete configuration file. Banana-specific additions: change Modulation and Color Panel FX; trigger playback via the integrated audio player; adjust the bus parametric EQ; remote-control any VBAN function. System-level functions: send a keyboard event to the system queue (to remote other applications); execute any program (with an optional command line); send an M.I.D.I. message to up to 2 devices; send VBAN-MIDI / VBAN-TXT requests.
- **Button Configuration dialog** (p.53, opened by right-clicking a button): 3 scripts of request(s) can be defined per button — one for the initial condition(s) sent on startup, one sent when the button is pushed, one sent when it's released. Fields: Button Name, Button Sub Name, Button Color (dropdown, 9 background colors including "Default"), Button Type (Push Button / 2 Positions), GPIO (dropdown, e.g. "no"), Keyboard Shortcut (dropdown of key/mouse combinations), "Exclusive Key" checkbox, Image filename (native resolution 130x108, "Select File Off"/"On" buttons for two separate images per state), Request For Initial State (script box), Request for Button ON / Trigger IN (script box + an event dropdown), Request for Button OFF / Trigger OUT (script box + event dropdown), M.I.D.I. Implementation (Learn checkbox + a Reset button + a display of the learned MIDI code, e.g. "#1 Note On C#2 (49)"), XINPUT (Enable checkbox, Ctrl dropdown "any", GamePad Button dropdown e.g. "START", for up to 4 connected gamepads), TRIGGER (Enable checkbox, Strip selector, In/Out threshold fields in dB e.g. -20.0/-20.0, Hold time in ms e.g. 1000, Input Mode e.g. "Pre-Fader"), HID Device Button (a "Config" button, connects directly to any HID device).
- **TRIGGER mechanics** (p.53): the button acts according to 2 thresholds against a selected input strip's level — the IN threshold (shown with a green cursor) pushes the button when level rises above it; the OUT threshold (red cursor) releases the button when level falls below it; HOLD time defines a minimum time the "gate" stays open once triggered.
- **Button Color palette** (p.54): 8 selectable background colors, numbered 1-8 (orange, yellow/olive, green, teal/cyan, blue, purple, magenta, red per the swatch shown).
- **Button Image** (p.54): a button can show a distinct image for its OFF state and its ON state, selected via "Select File Off"/"On"; native resolution 130x108 pixels; accepts BMP, PNG, JPG, or TIF; a larger image is reframed and scaled, a smaller one is centered. PNG smaller than native resolution correctly preserves a transparency layer including shadow effects. When a custom image is set, the keyboard shortcut label is not displayed on the button.
- **Voicemeeter Event trigger** (p.54): a button's Request for Button ON/OFF can instead be tied to a Voicemeeter-internal event via a dropdown: No event, Tape Play, Tape Stop, Tape Rec, Tape EndOfFile — i.e. the tape recorder's own transport events can directly drive a macro button's script.

## Voicemeeter Remote Requests (p.54-60)

- **Request syntax** (p.55): a request is a structured control/parameter name plus a value or string; some instructions are case-sensitive, and the manual recommends capitalizing the first letter of every word.
- **Numeric request examples** (p.55): `Strip(0).mute=1;` (mute ON, first strip), `Strip(0).mute=0;` (unmute), `Strip(0).mute+=1;` (toggle current mute state), `Bus(0).mono=1;` (set first bus to Mono mode), `Bus(0).gain=-10.0;` (set bus slider gain to -10.0 dB), `Strip(0).gain=+6.0;` (set strip slider gain to +6.0 dB), `Bus(0).gain+=3.0;` (add 3dB to current bus gain), `Strip(0).gain-=3;` (remove 3dB from current strip gain), `Command.Restart=1;` (restart audio engine).
- **String request example** (p.55): `Command.Load= "C:\My Documents\VMConfig1.xml";` (load a config file).
- **Strip index convention** (p.55): zero-based, and the count depends on edition — 3 strips on Voicemeeter Standard, 5 strips on Voicemeeter Banana (per this table's own note; Potato would extend further).

### Special functions: timed fade (p.58)

- **Strip().FadeTo / Bus().FadeTo** (p.58): sets the gain slider with a progressive fade to a target dB value over a given time (0 to 120,000 ms). String parameter with 2 values, e.g. `Strip(0).FadeTo=(-10.0, 500);` (fade to -10dB over 500ms), `Strip(0).FadeTo=(-20.0,2000);` (fade to -20dB over 2s), `Bus(0).FadeTo=(0.0,1500);` (fade bus to 0dB over 1.5s).
- **FadeBy** (p.58): same mechanics as FadeTo but with a relative dB change instead of an absolute target.
