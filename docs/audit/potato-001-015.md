# Voicemeeter Potato manual, pages 1-15

## Front matter (pp.1-7)

Cover page, first-installation/update/uninstall instructions (Run setup,
INSTALL/REMOVE buttons, mandatory reboot after each operation), online
support link, donationware licensing model (free to use, 30-day trial
before periodic activation prompts, license price adjustable by means,
volume licensing available), supported platforms list, and the Table of
Contents. No mixer controls or parameters on these pages — installation
mechanics and licensing terms are Windows-installer-specific and outside
this document's UI/engine scope. Noted, not itemized as entries.

- **Supported OS/APIs** (p.3): Windows XP(SP2)/VISTA/7/8/8.1/10, 32/64-bit;
  audio APIs MME, DX, WDM/WASAPI, KS, ASIO.

## Introduction (p.8)

- **Topology** (p.8): 8 audio inputs (5 physical + 3 virtual), 8 audio
  outputs (5 physical + 3 virtual), routed through 8 multichannel buses
  (A1, A2, A3, A4, A5, B1, B2, B3).
- **Bus parametric EQ** (p.8): every bus gets a 6-cell full parametric EQ,
  independently addressable per channel (1 to 8) — described use case:
  correcting a P.A. system from mono to 7.1, or (combined with Stereo
  Repeat mode) using the EQ as a stereo crossover to drive 2/3/4-way
  active speaker systems.
- **Two true aux sends** (p.8): manage external FX via an ASIO device;
  the ASIO channel must be assigned to the send/return functions in the
  system settings dialog box.
- **Virtual-input per-app mixer** (p.8): Potato displays applications
  connected to its virtual input with the same volume and mute control
  the Windows volume mixer offers per app.

## Introduction, matrix and diagram (p.9)

- **8x8 matrix** (p.9): every one of the 8 input strips can be mixed into
  any of the 8 bus outputs.
- **SEL button, per-bus input level** (p.9): bus assignment works like
  Banana, but Potato's SEL button per bus lets you set a strip's input
  level for one particular bus only — i.e. an independent gain per
  (strip, bus) pair, not one shared gain applied to every assigned bus.

## Audio interface types (p.10)

- **MME** (p.10): the original Windows Multimedia API; expected to work
  with any device, but latency can be ~100ms.
- **WDM** (p.10): handled by WASAPI, Microsoft's newer audio API; best
  performance/latency (<30ms); available since Windows Vista.
- **KS** (p.10): Kernel Streaming / Direct Kernel Streaming; low latency,
  available since Windows XP, but not every device exposes it.
- **WaveRT** (p.10): a miniport driver in Vista and later; latency
  comparable to KS.
- **Direct-X** (p.10): used by games and some audio software; latency
  usually comparable to MME.
- **ASIO** (p.10): Steinberg's low-latency, high-fidelity driver protocol.

## Audio HUB / next-gen engine overview (p.11)

- **VBAN** (p.11): send/receive audio streams to/from other computers on
  a local network (detailed later in the manual).
- **Voicemeeter Remote API** (p.11): lets client applications control
  every Voicemeeter feature — device aggregation, mixing/routing, MIDI,
  VBAN — programmatically. Ships `VoicemeeterRemote.dll` /
  `VoicemeeterRemote64.dll`.
- **Macro Buttons application** (p.11): installed alongside Voicemeeter;
  programmable buttons that act on Voicemeeter via a request script
  (detailed later).

## Quick startup / troubleshooting (p.12)

Procedural guidance only ("set Voicemeeter as your default device and
connect it to your main playback device"; general troubleshooting notes
about Windows' default-device assignment during driver install). No
distinct controls beyond what's covered on pp.13-15.

## Connecting to an audio device (pp.13-15)

- **Internal clock fallback** (p.13): Voicemeeter can run with no audio
  device selected at all, driven by its own internal clock, if output A1
  has no device selected.
- **A1 device-select button** (p.13): clicking it chooses the main output
  device for bus A (A1); ASIO recommended first if present, otherwise
  WDM, for best latency.
- **Exclusive-mode playback** (p.13): WDM/KS playback devices are used in
  exclusive mode by default, bypassing the Windows mixer and its own
  volume control.
- **Device selector grouping** (p.14): devices are listed by interface
  type (WDM, KS, MME, ASIO) and driver name, alphabetically, with icons
  to help identification.
- **A1 sample rate / engine sample rate** (p.14): A1's output device
  supports 32, 44.1, 48, 88.2, 96, 176.4, or 192 kHz — and this becomes
  the mixing engine's main sample rate and the Virtual ASIO points' rate.
  Every *other* input/output point can run at any sample rate Voicemeeter
  will accept independently of A1's.
- **"Open Windows Sound" button** (p.14): opens the Windows Sound dialog
  box to adjust a device's audio format.
- **Windows "Listen" caution** (p.14): Windows' per-device Listen option
  can interfere with Voicemeeter's routing; the manual recommends leaving
  it disabled unless deliberately needed.
- **Input level guidance** (p.14): if a selected input's level is too
  weak or too loud, check/adjust the device's own level or pre-amp gain
  (outside Voicemeeter itself).
- **Per-strip input device selector** (p.15): clicking a physical strip's
  "Stereo input" area selects that strip's capture device (e.g. strip #1
  → a microphone).
- **Strip input fallback when no device selected** (p.15): with no device
  assigned, a physical strip can still receive audio from a VBAN stream,
  or from ASIO input on the ASIO device currently selected as output A1.
- **Driver recommendation** (p.15): WDM (available since Vista) preferred
  for latency/performance; MME only as a fallback when WDM is absent or
  malfunctioning for a given device.
