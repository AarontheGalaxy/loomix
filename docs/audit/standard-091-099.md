## License activation, continued (p.91-93)

Pure licensing/account mechanics, brief for completeness only (clearly out of scope for a Loomix feature-parity audit): a webshop "My License" page lists owned licenses with Challenge/Response codes, a Download link, an Order reference, and remaining license "Regen" count; the in-app License dialog takes a registered e-mail + response code and an Activate button, storing an authentication certificate locally once activated (shows "ACTIVATED" in green); an offline/manual path exists if the activation server can't be reached, via a copy-pasted certificate string (starts with `>` and ends with `<`) retrieved from the same webshop account page.

## Known Issues / Recommendations (p.94-95)

Real troubleshooting guidance, not settings, but documents several behaviors worth recording precisely:

- **"No sound anymore on my computer!"** (p.94): Voicemeeter must be *running* to pass audio if set as the Windows default device -- "like switching ON your mixing console." While running, it can take exclusive access to its selected output devices (A1, A2, A3...), intentionally preventing other applications from also using them directly -- by design, to avoid routing conflicts (compared to a real mixing console: "you connect nothing else to this amplifier").
- **"Voicemeeter does nothing if you don't use it"** (p.94): the application and its virtual audio drivers are inert when not actively configured as the audio path -- "they cannot disturb or corrupt your system." A no-sound problem traces to Windows' own default-device configuration, or to some other app (named examples: Zoom, Discord, Spotify, Games, OBS) still pointed at Voicemeeter from an earlier setup.
- **"Output A1, A2, A3... are not exactly synchronized"** (p.94): every physical I/O point runs independently; with up to 5 different output devices in play, their audio can drift out of exact sync (audible as a small echo between speaker outputs). Described explicitly as expected behavior ("normal, according to technical constraint"), correctable via a per-output **Monitoring Synchro Delay** line (ms) in the System Settings dialog -- the screenshot shows delay fields for OUT A1 through **OUT A5** even in the Standard-edition manual, again implying the underlying mechanism addresses more outputs than the Standard console UI itself ever shows.
- **"Voicemeeter Audio Stream can be stopped (no more sound, no meter display)"** (p.94): can happen when Windows audio configuration changes, a USB device is plugged/unplugged, or another program claims the same device. Fix: restart the audio engine, or re-select an output/input device -- this auto-restarts the stream, unless the device is genuinely now held by another process.
- **"Voicemeeter Audio Engine works only if the device selected for output A1 is running"** (p.95): if no device is available, select nothing for A1 to fall back to the internal clock instead.
- **"Audio Stream becomes bad (sound is choppy, crackling, discontinued)"** (p.95): if the stream isn't stable over time with too much cut in the sound, try a different audio interface or buffer size. Specific named case: Discord can misbehave at any sample rate other than 48 kHz, so the Voicemeeter virtual output device Discord is reading from should be explicitly set to 48 kHz (via Windows Sound's device Properties > Advanced tab format dropdown).
- **"Windows Update can disturb audio"** (p.95): Windows 10/11 updates can silently change default settings or rules -- named examples: microphone Privacy settings blocking Voicemeeter's access to recording devices, and Windows 11's "power throttling" causing an unstable stream when the application window is minimized.

## VB-Audio Device Checker (p.96-97)

- **`VBDeviceCheck.exe`** (p.96): still reachable from the Voicemeeter menu, but no longer auto-run at startup (unlike earlier versions). Originally built to detect a Windows-Update-triggered driver reinstall corruption by checking each legacy virtual driver's icon, pin name, and version info against what's expected; note that pin name/icon are now user-changeable with the current driver, weakening that specific check. Checks a long list of both legacy and current virtual devices (VB-Audio Virtual Cable, Cable A through D, MT128 Virtual I/O, Hi-Fi Cable, VoiceMeeter VAIO / AUX VAIO / VAIO3, VB-Audio Matrix VAIO, VB-Audio Voicemeeter VAIO) and prints version-mismatch warnings plus an overall CONCLUSION line (e.g. "OK (nothing bad detected)").
- **Driver consolidation note** (p.96): "the 3x VoiceMeeter drivers are no more installed on Windows 10 or higher. Only Voicemeeter VAIO driver is installed instead... a single driver with 8 I/O to simplify the maintenance and bring more power." Warnings from this tool about the legacy 3-driver scheme can be safely ignored on modern Windows.
- **Audio Device List** (p.96-97): a sub-view of the same tool, listing every installed VB-Audio virtual device with its current MIX Format and Exclusive-mode properties -- explicitly noted as sometimes stale: "parameters seems to be not always updated correctly."
- **Devices menu** (p.97): Show Device List, Refresh Device List.

## Where settings files are stored (p.97)

- **Storage location** (p.97): all Voicemeeter and MacroButtons settings are stored as XML files under "My Documents\Voicemeeter".
- **Daily settings snapshot mechanism, confirmed** (p.97): for MacroButtons and each of the three Voicemeeter editions independently, the config manager keeps **two rolling backup copies** in addition to the live settings -- a "Today" file (the configuration state as of the start of the current day) and a "Yesterday" file (whatever was in use the day before). Filenames observed in the folder listing: `VoicemeeterStandard_LastSettings.xml`, `VoicemeeterStandard_TodaySettings.xml`, `VoicemeeterStandard_YesterdaySettings.xml` (and the equivalent `VoicemeeterBanana_*` / `VoicemeeterPotato_*` triples), `MacroButtonConfig.xml` / `MacroButtonConfig_Today.xml` / `MacroButtonConfig_Yesterday.xml`, plus per-edition preset folders `Scene_Standard`, `Scene_Banana`, `Scene_Potato`, a `VoiceModeler_Preset` folder, and separate activation-log files per licensed extension.

## Command Line Installation / Voicemeeter Command Line (p.98)

- **Setup program flags** (p.98): `-h` (hide GUI), `-i` (install), `-u` (uninstall). Recommended sequence for an automated update: uninstall the previous version, reboot, install the new version, reboot again.
- **Restart the audio engine from a shortcut** (p.98): `Voicemeeter.exe -R` (or `-r`) -- useful, for example, to reactivate a USB headset already selected as a Voicemeeter hardware input but which was unplugged and replugged (the audio engine must be restarted to pick it back up).
- **Launch with a specific configuration file** (p.98): only takes effect if Voicemeeter is not already running (does nothing otherwise). `-l"filename.xml"` or `-L"filename.xml"` for a file next to the executable; `-l"subfolder\filename.xml"` for one in a subdirectory; `-l"c:\folder\filename.xml"` for an absolute path. (The manual doesn't spell out any difference in behavior between the lowercase `-l` and uppercase `-L` forms beyond showing them as interchangeable "or" alternatives in every example -- recorded as written, not resolved further.)

## Registry Parameters (p.99)

Expert-only, explicitly warned against modifying without guidance from the vendor's support channels; all under `HKEY_CURRENT_USER\VB-Audio\VoiceMeeter`.

- **`DelayedStartS`** (p.99): countdown in seconds (default 5) before the audio engine starts on Voicemeeter's own startup, shown as a growing bar/countdown over the A1/A2/... device-selection area -- gives audio services and drivers time to finish starting first; a driver not ready when the engine starts won't work until the engine is manually restarted.
- **`preferredResolution`** (p.99): preferred bit resolution. Banana and Potato default to 24 bits; **Voicemeeter Standard always uses 16 bits with the Windows Audio Interface** regardless of this setting. Actual final resolution is still negotiated with the real audio interface, which can force a different one anyway.
- **`MaxMonDelayMS`** (p.99): default 500ms, the maximum value selectable for the BUS monitoring delay options (System Settings dialog); redefinable via this key from 500ms up to 5000ms (5 seconds).
- **`PreRecordingTimeMax`** (p.99): 10 to 60 seconds (default 20), sets the pre-recording buffer's memory allocation at startup (example given: roughly 90MB for 60 seconds at 48kHz).
- **`TimerResolution`** (p.99): default `1` (forces the system timer resolution to 1ms); set to `0` to use a 0.5ms system timer resolution instead.
- **`AutoUpMixMode`** (p.99): **exact, primary-source confirmation of a feature already flagged from an earlier review pass** ("optional automatic Up Mix detection," previously only paraphrased) -- verbatim: "If set to 1, this mode act on upmix BUS MODE by detecting signal level and deduce if the signal is stereo or multichannel (it is considered as multi channel if signal above -80 dBFs is detected in channel 3,4,5 ... in this case the UpMix is not applied)." Precise threshold: **-80 dBFs on channels 3, 4, and 5**. Default is **0 (off)** -- this is an opt-in registry toggle, not a UI-exposed mixer control anywhere in the product, which is itself a relevant fact for however this gets scoped: the reference product doesn't put this in its console UI either.
- **Warning, verbatim** (p.99): "Other registry values must not be modified directly."
- **`EngineMode`** (p.99, "AUDIO EXPERT / DEVELOPERS" subsection): a bit field for WASAPI-engine-related features, must be ZERO by default -- "these historic modes are not tested anymore in our dev cycle." Exact bits: `0x00000001` = MODE_SWIFT, `0x00000100` = INPUT EXCLUSIVE MODE, `0x00000200` = OUTPUT EXCLUSIVE MODE ("set anyway in Voicemeeter" -- printed exactly as such, meaning output exclusive mode is apparently controlled separately/always-effectively-set by Voicemeeter itself regardless of this particular bit; not elaborated further in the manual). **This directly confirms, at the exact registry-bit level, that "SWIFT mode" and "WDM Input Exclusive Mode" -- both already flagged as vendor-deprecated/disabled options on p.79-81 -- are these two literal `EngineMode` bits**, now fully corroborated as one and the same feature described from two different angles (the Options dialog UI, and this registry documentation) in this manual.
